# 시스템 명세 (분리 설계 초안)

보고서 v2의 4장을 시스템 단위로 나눈 문서다. 형식은 변경될 수 있다. 상태: 초안.

---

## 1. 분리 원칙

1. **한 상태는 한 시스템만 쓴다.** 다른 시스템은 읽기만 하고, 바꾸고 싶으면 사건으로 요청한다 (단일 작성자).
2. **시스템은 서로를 호출하지 않는다.** 공유 상태 키를 읽고 사건을 내보낼 뿐이다.
3. **연결은 코드에 쓰지 않는다.** 한 시스템이 내는 키(`emits`)가 다른 시스템이 기다리는 키(`on`)와 같으면 자동으로 이어진다. 연결 관계는 데이터에서 계산한다.
4. **시스템은 순수 함수다.** `step(상태, 입력) → (새 상태, 사건 목록)`. 파일 쓰기와 현재 시각 읽기는 하지 않는다.
5. **시스템은 이름을 모른다.** 오브젝트·장소·행동의 이름은 데이터에만 있다.
6. 원 기획서의 8개 생활 시스템(공간·위생·식생활·시간·효율화·유지·자기 돌봄·감각정서)은 **모듈이 아니라 콘텐츠 분류 태그**다. 모듈은 아래 층 구조를 따른다.
7. **변화는 인과와 개입으로 나뉜다.** 변화 규칙은 앞선 상태와 경과 시간만으로 다음 상태를 정하며 난수를 쓰지 않는다. 난수는 이벤트(개입)·행동 판정·문장 선택에만 쓴다.

## 2. 층 구조와 시스템 목록

| 층 | 시스템 | 한 줄 역할 |
|---|---|---|
| 기반 | **시계** | 게임 시간, 하루 경계, 주차, 시연 모드, 부재 Δt |
| | **난수** | 시드 고정 난수 |
| | **기록** | 추가만 되는 불변 사건 로그 |
| | **저장** | 직렬화·복원, 쓰기는 이곳만 |
| 세계 | **세계 상태** | 오브젝트, 특징, 장소 그래프, 상태 키 (진실 상태) |
| | **변화 규칙** | 오염·부패 같은 변화와 단계 사슬, 번짐 |
| | **자원** | 시간·에너지·돈·소모품·식재료의 유한 풀, 공급과 분해 |
| | **인물** | 인물 정의, 감각 프로파일, 허용 한계, 일과 |
| 행위 | **행동** | 행동 정의, 유효성 검사, 비용, 효과 |
| | **일정** | 약속, 직장 블록, 지연 효과 예약 |
| | **이벤트** | 조건 평가, 가중치 추첨, 선택지, 쿨다운 |
| | **컨디션** | 여유·에너지·긴장, 음성 되먹임, 모드 |
| | **밖의 하루** | 직장 블록을 요약 사건 카드로 생성, 귀가 시 반영 |
| | **자율 행동** | 인물이 욕구·습관·환경·인지를 보고 다음 행동을 고름 |
| 앎 | **감각** | 자극 → 지각 계산 (강도 × 민감도) |
| | **인지** | 알아챔·이해 단계, 해금 조건, 증상 |
| | **습관** | 반복 행동의 강도, 기본값 제안, 자동 행동 |
| 표현 | **문장 엔진** | 상태 키 → 문장 조각 조회, 호흡, 하루 정산 |
| | **화면** | 장소 선택, 장면, 오버레이 (텍스트 러너 → 웹) |
| 도구 | **검증기** | 데이터 관문 |
| | **콘텐츠 팩** | 선택적 데이터 묶음 (성숙한 주제 모듈 포함) |

---

기반 층(시계·난수·기록·저장)과 공통 원시 약속(번호·상태 키·사건 봉투)의 구체 규칙은 `기반층-명세.md`에 있다. 변화 규칙의 하위 설계인 번짐(개체, 매질, 계통)은 `번짐-명세.md`에 있다.

## 3. 시스템별 계약

각 줄은 "무엇을 소유하고, 무엇을 읽고, 무엇을 내고 받는가"다.

| 시스템 | 소유 (쓰는 상태) | 읽는 것 | 내는 사건 | 받는 사건 | 슬라이스 |
|---|---|---|---|---|---|
| 시계 | 현재 시각, 일, 주차 | — | `tick` `day_open` `day_close` `week_close` `absence` | — | ○ |
| 난수 | 시드·진행 위치 | — | (값 제공) | — | ○ |
| 기록 | 사건 로그 | — | — | 모든 사건 | ○ |
| 저장 | 저장 파일 | 모든 상태 | `saved` | `day_close` | ○ |
| 세계 상태 | 오브젝트 특징, 위치 | 규칙 정의 | `state_changed` | 규칙·행동의 효과 요청 | ○ |
| 변화 규칙 | 진행도, 단계 | 세계 상태, 시계 | `stage_advanced` `symptom_shown` | `tick` `absence` | ○ |
| 자원 | 풀 잔량 | 규칙(공급·분해) | `resource_low` `resource_empty` | 행동 비용, `tick` | ○ |
| 인물 | 인물 정의 (정적) | — | — | — | ○ (1명) |
| 행동 | (없음, 효과를 요청만 함) | 세계 상태, 자원, 인지, 인물 | `action_done` `action_blocked` | 플레이어 입력 | ○ |
| 일정 | 약속·예약 큐 | 시계 | `commitment_due` `delayed_effect` | `action_done`, `event_fired` | △ |
| 이벤트 | 쿨다운, 발생 기록 | 상태, 인지, 일정, 난수 | `event_fired` `choice_made` | `tick` `day_open` | △ |
| 컨디션 | 여유, 에너지, 긴장 | 인물 (집의 영향은 지각·행동을 거쳐 다음 단계에 반영, `품질판-명세.md` 5장) | `condition_changed` `mode_entered` | `tick` `day_close` `outside_day_done` `action_done` | ○ |
| 밖의 하루 | 오늘의 밖 카드 | 인물, 일정, 난수 | `outside_day_done` | `day_open` | △ |
| 자율 행동 | (없음, 선택만 낸다) | 컨디션, 인물의 인지, 습관, 환경, 일정, 난수 | `action_chosen` | `tick` `mode_entered` | ○ |

세 시스템의 상세는 `인물-명세.md`에 있다. 지켜보는 구조에서는 **인지가 인물의 것**이다.
| 감각 | 지각 값 (파생) | 인물, 세계 상태 | `stimulus_perceived` | `state_changed` | ○ (최소) |
| 인지 | 인지 단계 | 해금 조건, 지각, 사건 | `awareness_up` | `symptom_shown` `stimulus_perceived` `action_done` | ○ |
| 습관 | 습관 강도 | 기록 | `habit_formed` | `action_done` | △ (2~3개) |
| 문장 엔진 | (없음) | 모든 상태, 기록, 인물 | `text_ready` | 모든 사건 | ○ |
| 화면 | 화면 상태 | 모든 상태 | 플레이어 입력 | `text_ready` | ○ (텍스트) |
| 검증기 | (없음) | 모든 데이터 | 검증 결과 | — | ○ |
| 콘텐츠 팩 | 팩 활성 여부 | — | — | — | × |

## 4. 연결이 생기는 방식

### 4-1. 계약의 세 종류

- **상태 키 읽기**: 세계 상태의 키(`신발|밑창:더러움|현관`)를 여러 시스템이 읽는다.
- **사건 구독**: 사건 이름을 기다리는 시스템이 반응한다. 구독 관계는 데이터에 선언한다.
- **효과 요청**: 상태를 바꾸고 싶은 시스템은 소유자에게 `effect` 사건을 낸다. 직접 쓰지 않는다.

### 4-2. 주요 상호작용 표

| 낸 쪽 → 받는 쪽 | 사건 / 키 | 생기는 효과 |
|---|---|---|
| 시계 → 규칙 | `tick` `absence` | 변화 진행. 부재는 큰 Δt로 같은 규칙을 계산 |
| 규칙 → 감각 | `state_changed` | 자극 발생 (냄새, 소리, 얼룩) |
| 인물 + 감각 → 인지 | `stimulus_perceived` | 민감도에 따라 알아채는 시점이 달라짐 |
| 규칙 → 인지 | `symptom_shown` | 증상이 해금 조건을 충족 → 시야 확장 |
| 인지 → 행동 | `awareness_up` | 새 행동이 열리고 화면에 대상이 보임 |
| 행동 → 자원 | 비용 | 풀이 줄고 바닥나면 `action_blocked` |
| 행동 → 세계 상태 | `effect` | 닦기가 `밑창:더러움`을 내림 |
| 행동 → 기록 → 습관 | `action_done` | 같은 맥락 반복 시 강도 상승 |
| 습관 → 행동 | 기본값 제안 | 선택지의 기본 위치, 서술 속 자동 행동 |
| 행동 → 일정 | 지연 효과 예약 | 과음 → 내일 아침 사건 |
| 일정 → 시계·자원 | 약속이 시간을 차지 | "청소 더 할까?"의 선택 비용 |
| 이벤트 ← 상태·인지·일정 | 조건 평가 | 상태가 맞으면 발생, 쿨다운 적용 |
| 모든 사건 → 기록 → 문장 엔진 | 사건 + 상태 태그 | 문장 조각 조회, 하루 정산 산문 |
| 콘텐츠 팩 → 이벤트·행동·문장 | 데이터 주입 | 활성일 때만 합쳐짐. 검증기가 등급 태그를 강제 |

### 4-3. 틱 처리 순서

> **정정 대기 (2026-11-05)**: 이 순서는 매 틱을 전제한다. 확정한 시간 모델은 고정 틱 없는 **이벤트 예약**이다. 시간 모델 문서가 이 절을 대체한다 (`품질판-명세.md` 11장). 컨디션이 집 환경을 직접 읽는 부분도 `품질판-명세.md` 5장으로 바뀌었다.

한 번의 처리는 항상 같은 순서로 돈다 (처리 순서 고정).

1. 시계가 `tick` 발행
2. 변화 규칙이 진행·전파 → `state_changed`, `symptom_shown`
3. 자원이 분해·공급 반영
4. 감각이 지각 계산 → 인지 갱신
5. 일정이 만기 약속·지연 효과 발동
6. 이벤트가 조건 평가·추첨
7. 플레이어 입력 → 행동 검사·실행 → `effect` 반영
8. 기록에 추가
9. 습관 갱신
10. 문장 엔진이 문장 조립 → 화면

부재 시에는 1~3을 큰 Δt로 한 번에 돌리고, **마지막으로 본 상태 + 1단계 상한**을 적용한 뒤 귀환 장면으로 이어진다.

## 5. 추적 예시: 냉장고 음식이 상한다

각 시스템이 자기 일만 하는데 연결이 어떻게 생기는지 보여 주는 예다.

| 순서 | 시스템 | 일 |
|---|---|---|
| 1 | 자원 | 식재료 풀의 유통기한 분해가 0에 닿음 → `resource_empty` (식재료#17) |
| 2 | 변화 규칙 | `음식|상태:상함|냉장고` 생성 → 진행도 누적 시작 (가중치는 현재 더러움) |
| 3 | 감각 | 후각 자극 발생. 인물의 후각 민감도 곱 |
| 4 | 인지 | 자극이 임계를 넘으면 `awareness_up` (냄새 알아챔). 못 넘으면 계속 모름 |
| 5 | 변화 규칙 | 임계 도달 → `stage_advanced`: 벌레 발생(냉장고) |
| 6 | 변화 규칙 | 벌레의 `on` 키가 장소 그래프로 주방과 이어짐 → 주방 침투 단계 진행 |
| 7 | 이벤트 | "냉장고 문을 열었다" 조건 충족 → 발생, 선택지 제시 |
| 8 | 행동 | 버리기/닦기 유효성 검사 (비닐장갑 보유?), 자원 비용 |
| 9 | 기록 → 문장 엔진 | 사건과 상태 태그로 조각 조회, 하루 정산에 반영 |

사람이 "상함 → 벌레 → 주방"을 직접 이은 곳은 없다. 키가 맞아서 이어진 것이다.

## 6. 의존 방향

```
기반 (시계·난수·기록·저장)
  ↑
세계 (상태·규칙·자원·인물)
  ↑
행위 (행동·일정·이벤트)   앎 (감각·인지·습관)
  ↑                        ↑
표현 (문장 엔진·화면)  ←  모든 층의 읽기
도구 (검증기·팩)         데이터 전체를 검사
```

- 아래 층은 위 층을 모른다. 위 층은 아래 층을 읽을 수 있다.
- 같은 층끼리는 사건과 상태 키로만 소통한다.
- 표현 층은 읽기 전용이다.

## 7. 슬라이스에서의 구성

- 포함: 시계, 난수, 기록, 저장, 세계 상태, 변화 규칙, 자원, 인물(1명), 행동, 감각(최소), 인지, 문장 엔진, 검증기, 화면(텍스트).
- 최소 구성: 일정(약속 1개), 이벤트(5~10개), 습관(2~3개).
- 제외: 콘텐츠 팩, 인물 간 상호작용, 웹 화면 오버레이 (텍스트 러너 이후).

## 8. 미정 사항

1. 감각을 인지에서 독립 시스템으로 둘지, 인지의 입력 단계로 합칠지 (현재안: 분리 유지, 데이터는 인물이 소유).
2. 효과 요청의 형식 (사건으로 통일할지, 소유자 함수 호출 목록으로 둘지).
3. 사건 이름과 상태 특징의 통제 어휘 초안.
4. 구독 관계를 시스템별 파일에 둘지, 한 곳에 모을지.
5. **거래(중고 판매) 시스템**: 물건이 세계를 떠나는 유일한 길이다. 슬라이스 밖이지만 시스템 목록에 추가해야 한다.
