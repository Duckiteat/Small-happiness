# 요리 설계 (요리법 · 칼질 · 설거지) — 된장찌개를 첫 요리로

작성일 2026-11-08 · 상태: **1차 구현 (작가 확정 2026-11-08, 7장)** · 근거: 작가 요청("된장찌개로 하자. 요리는 요리법에서 가져와서 하루가 칼질에 요리도 가능하게 할 수 있나? 칼과 도마, 설거지도")

---

## 1. 결론

- **할 수 있다.** 필요한 재료 상태(`cut`: 통째·덩어리·썰기·다지기), 더러움(`dirt`), 가열 온도(`heat`: 끓음), 물(`water`), 불(`flame`), 싱크대·가스레인지가 이미 있다. 새로 만들 것은 도구(칼·도마·냄비), 요리법 데이터, 칼질·설거지 행동이다.
- **하루씨가 "무엇을 만들지"를 정하는 부분이 지금 없다.** 하루씨는 할 수 있는 행동 중 정의 번호 순으로 첫 번째를 고르는 기본안이고 목표가 없다. 요리법을 따라 여러 단계를 이으려면 오늘 무엇을 만드는지가 필요하다 (3장 결정 1).
- **양(몇 숟갈)은 없다.** 재료는 개체 하나가 통째로 쓰인다 (4장 한계).

## 2. 이미 있는 것

| 필요한 것 | 지금 있는 것 |
|---|---|
| 재료 | 된장 · 대파 · 양파 · 애호박 · 두부 (이번에 더함, 보관 기간은 임시값) |
| 썰기 | 특징 `cut` (통째 · 덩어리 · 썰기 · 다지기), 썰면 상하는 속도가 빨라진다 (진행 법칙의 입력) |
| 끓이기 | 가열 온도 `heat`의 `끓음`, 가스레인지 불 `flame`, 물 `water` |
| 설거지 | 특징 `dirt` (깨끗 · 먼지 · 더러움 · 심함), 싱크대의 물과 배수 |
| 요리법을 담을 곳 | 제공 행동(`offers`): 조건(`when`)과 결과(`effect`)로 재료·도구·불의 상태를 적을 수 있다. 새 정의 종류는 필요 없다 |

## 3. 제안 (단계)

1. **도구 정의**: 칼, 도마, 냄비(물을 담고 끓일 수 있음). 각자 `dirt`를 가진다.
2. **칼질 행동**: 재료를 칼과 도마가 깨끗할 때 썰면 `cut`이 오르고, 칼과 도마가 더러워진다.
3. **설거지 행동**: 싱크대에 물이 있을 때 더러운 도구를 씻으면 깨끗해지고 물이 줄어든다 (배수로 사라진다).
4. **된장찌개 요리법**: 냄비에 물을 끓이고(`heat`=끓음), 된장 · 애호박 · 양파 · 두부 · 대파를 썰어 넣고, 끓으면 찌개가 되고 재료는 쓰여서 사라진다. 찌개는 새 음식 정의(가열 음식)로 생긴다.
5. **하루의 계획**: 오늘 무엇을 만들지를 정한다 (아래 결정 1).

## 4. 작가에게 묻는 것

1. **무엇을 만들지 누가 정하나?** (가) 하루 계획에 식사마다 메뉴를 적는다. (나) 규칙으로 정한다 (김치가 시어졌으면 김치찌개처럼, 이미 `찌개용` 의미가 있다). 권장: 첫 요리는 (가), 점수 매기기(구현 계획 18번)가 생기면 (나)를 섞는다.
2. **양을 모델에 넣을까?** 지금은 재료 하나가 통째로 쓰인다. 된장은 한 번에 조금 쓰고 오래 남는 재료라서 부자연스럽다. 권장: 첫 요리는 통째 소모로 하고, 한계 등록부에 올린다.
3. **육수(국물)를 상태로 둘까?** 끓인 물이 육수가 되는 중간 상태를 따로 둘지, 냄비의 `heat`=끓음과 재료 상태로만 충분한지. 권장: 따로 두지 않는다.

## 5. 확인하지 못한 것

- 요리법의 출처: 작가님이 가진 요리법 자료(형식)가 있으면 그 형식을 따르고, 없으면 일반적인 된장찌개로 시작해 `tuned:false`로 표시한다.
- 칼질·설거지에 걸리는 시간과 물의 양은 모두 임시값이 된다.

## 6. 나중: 숙련과 동시 진행 (요리법·칼질 다음)

작성일 2026-11-08 · 상태: **나중에 할 일 (아직 설계만)** · 근거: 작가 질문("숙련되면 요리하면서 다른 일도 같이 해서 하루의 시간을 아낄 수 있나")

- **지금 되는 것**: 기다리는 동안의 일은 규칙이 처리하므로(밥솥은 켜는 데 1분, 밥 짓기 30분은 규칙) 하루씨의 손은 비어 있다. **안 되는 것**: 손이 가는 행동은 한 번에 하나뿐이다 (행동 층에 `busyUntil` 하나). 숙련을 담을 인물 상태(4b층)도 비어 있다.
- **만든다면**: (1) 행동을 손이 가는 시간과 지켜보기만 하는 시간으로 나눈다. (2) 숙련을 인물의 상태 사다리로 둔다 (요리·청소 …). (3) 숙련이 높으면 손이 가는 시간이 줄고(정수 계수 표) 지켜보는 시간에 끼울 수 있는 일이 늘어난다. (4) 같은 종류의 행동을 끝낼 때마다 쌓여 경계를 넘으면 한 칸 오른다 (진행 층과 같은 방식, 난수 없음).
- **작가 결정이 필요한 것**: (가) 숙련이 오르는 방식 — 해 본 횟수만 / 안 하면 녹슮. (나) 동시에 몇 가지까지 — 둘까지 / 숙련에 따라 더. (다) 끼울 수 있는 일 — 기다리는 일에만 / 손이 가는 일 둘을 나눠서도.
- **권장**: 횟수만(녹슮은 나중), 둘까지, 기다리는 일에만. 순서는 요리법과 칼질이 만들어진 다음이다 (손이 가는 시간과 기다리는 시간을 나눌 재료가 필요하다).

## 7. 작가 결정과 1차 구현 (2026-11-08)

**결정**: (1) 메뉴는 하루 계획에 적는다. (2) 양을 지금 넣는다. (3) 육수 상태를 둔다. (4) 요리법은 일반적인 된장찌개, 임시값.

| 무엇 | 어떻게 |
|---|---|
| 메뉴 | 일정 구간 `{ kind: "meal", from, to, menu: "doenjang_jjigae" }`. 요리법의 단계(행동의 `menu`)는 그 구간에만, 한 끼에 한 번 |
| 양 | 특징 `amount` (없음 · 조금 · 반 · 넉넉 · 가득). 행동의 `uses: [{ key, steps }]`가 지금 단계에서 steps칸 내린다. 모자라면 하지 않는다 |
| 국물 | 냄비의 `soup` (없음 · 맹물 · 우리는 중 · 육수 · 된장 풂 · 찌개)와 `filling` (없음 · 채소 · 두부까지 · 대파까지) |
| 도구 | 칼·도마·냄비 (`objects-kitchenware.json`). 썰면 칼·도마가 더러워지고, 먹으면 냄비가 더러워진다 |
| 재료 | 된장 · 국물용 멸치 1칸, 양파 · 애호박 · 두부 2칸(반), 대파 1칸 (임시값) |

**순서** (`content/scenarios/kitchen-stew.json`, 첫날 저녁): 두부·대파·양파·애호박 썰기(각 3분) → 싱크대에 물 받기 → 냄비에 붓기(맹물) → 불 붙이기 → 멸치 넣기(우리는 중) → 10분 → 육수 → 된장 풀기 → 양파·애호박 → 두부 → 대파 → 5분 → 찌개(주방에 구수한 냄새) → 불 끄기 → 먹기(20분) → 물 받기 → 설거지(냄비·칼·도마). 메뉴가 없는 둘째 날 점심에는 아무것도 하지 않고, 둘째 날 저녁에는 이미 썬 재료를 다시 썰지 않고 남은 양에서 쓴다.

**확인한 것**: `test/stew.test.ts` 6개 (순서·시간, 한 끼 한 번, 메뉴 없는 끼니, 남은 양, 설거지, 감사 위반 0과 고친 기록 3종을 잡음). 셋째 날까지 끓이면 양파·애호박·두부가 없어 된장을 푼 국물에서 멈추고 불은 한 시간 뒤 저절로 꺼진다 (임시 시나리오로 확인, LIM025).

**확인하지 못한 것 / 남은 한계**: 칸 사이의 실제 양, 썰기·끓이기 시간은 임시값이다. 썰기가 개체 전체에 걸린다(LIM023). 찌개는 냄비의 상태라 식거나 쉬지 않는다(LIM024). 재료가 모자랄 때 대신하거나 장을 보지 않는다(LIM025). 감사는 일정의 메뉴를 대조하지 못한다(LIM026). 숙련과 동시 진행(6장)은 아직이다.
