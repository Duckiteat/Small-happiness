# 기반층 명세 (초안)

시스템 명세의 "기반" 층을 구체화한 문서다. 모든 시스템이 공유하는 원시 약속(0장)과 그 위의 네 시스템(기록, 난수, 시계, 저장)을 다룬다. 타입 표기는 설명용이며 구현 언어는 TypeScript를 가정한다. 상태: 초안, 7장의 기본안은 확정 전. 구현 현황: 0장(번호·상태 키·사건 봉투), 1장 기록, 사전은 `src/core/`에 구현됨. 2장 난수, 3장 시계, 4장 저장은 미구현.

---

## 0. 공통 원시 약속

### 0-1. 번호 (ID)

- 정의 번호: `접두 + 6자리 숫자`. 의미 없는 고정 번호다.

| 접두 | 대상 | 접두 | 대상 |
|---|---|---|---|
| OBJ | 오브젝트 정의 | AWR | 인지 노드 |
| PLC | 장소 | FRG | 문장 조각 |
| RUL | 변화 규칙 | CHR | 인물 |
| ACT | 행동 | HAB | 습관 정의 |
| EVT | 이벤트 정의 | CMT | 약속 정의 |
| ITM | 물품·자원 종류 | | |

- 인스턴스 번호: `정의번호#순번` (예: `OBJ000001#1`은 신발 한 켤레). 순번은 단조 증가하며 재사용하지 않는다.
- 기록 번호: `L` + 숫자, 기록이 붙인다 (1로 시작, 빈틈 없음).
- 이름·문장은 번호에 붙은 꼬리표다. 바꿔도 연결이 끊기지 않고, 지운 번호는 다시 쓰지 않는다.
- 패치의 새 항목은 임시 번호(`OBJ+1`)를 쓰고 병합 때 실제 번호로 바뀐다.

### 0-2. 수량은 정수

- 시간은 **분**, 돈은 원, 자원은 개수 또는 단위 정수, 진행도는 천분율(0~1000)이다.
- 표시 오류와 누적 오차를 피하려고 시간·자원은 정수로 둔다. 엄격한 규칙은 아니다.

### 0-3. 상태 키와 값

```
상태 키   = 인스턴스 | 부위 : 특징           예) OBJ000001#1|sole:dirt
상태 값   = 단계(정수, 0부터)                 예) 2
```

- **특징**은 통제 어휘다 (dirt, rot, smell, wet, clutter, bug, dust …). 특징마다 단계의 의미표가 있다 (dirt: 0 깨끗, 1 먼지, 2 더러움, 3 심함).
- **위치**는 키가 아니라 인스턴스의 속성(`at: PLC…`)이다. 장소 간 번짐은 장소 그래프로 처리한다.
- **패턴**은 `정의 | 부위 : 특징 @ 단계 조건`이다. 규칙의 `on`(기다리는 상태)과 `emits`(내는 상태)가 패턴이고, 한쪽의 `emits`가 다른 쪽의 `on`과 맞으면 자동으로 사슬이 이어진다.
- 진행도(진행 중인 변화)는 상태가 아니라 **변화 규칙이 소유**한다. 단계를 바꾸는 것은 세계 상태가 한다 (단일 작성자).

### 0-4. 사건 봉투

```ts
interface GameEvent {
  seq: string;          // L000123 — 기록이 부여
  t: number;            // 절대 게임 시각(분)
  type: EventType;      // 통제 어휘. 유형마다 data 스키마가 있다
  src: SystemId;        // 낸 시스템
  cause: string | null; // 원인 사건의 seq (인과 추적)
  data: Record<string, JsonValue>;
}
```

- 사건은 **불변**이다. 잘못된 사건은 고치지 않고 `retract`(철회) 사건으로 표시한다.
- `cause`로 연쇄를 거슬러 올라갈 수 있다 (예: 이 벌레는 어느 부패에서 왔나). 하루 정산과 디버깅의 근거가 된다.
- 효과 요청은 `effect_request` 사건이며 받을 시스템이 `data.to`에 들어간다.
- **근거 참조 `data.via`** (2026-11-07): 사건은 직전의 어떤 사건이 일으켰나(`cause`)와 어떤 규칙·행동·법칙·감각이 만들었나(`via`)를 따로 적는다. 사전 `event_type`의 `via_kinds`가 정한 유형은 via가 필수이고, 기록이 via 없는 사건을 받지 않는다. 모양과 종류는 `영수증-명세.md` 7장.

### 0-5. 인과와 개입의 분리

세계의 변화에는 출처가 둘 있다.

| 출처 | 설명 | 난수 |
|---|---|---|
| **인과 (변화 규칙)** | 앞선 상태와 경과 시간만으로 다음 상태가 정해진다 | **사용 금지** |
| **개입 (이벤트·행동 판정)** | 비, 연락, 방문 같은 외부 개입과 성공·실패 판정. 조건은 상태에 의존하고, 발생과 결과에는 난수를 쓸 수 있다 | 사용 |

- 변화 규칙의 함수 모양은 `(상태, 경과시간) → 효과 목록`이며 난수 생성기는 인자로 주어지지 않는다. **구조로 강제**하므로 별도 검사 코드가 필요 없다.
- 이는 "활동 사이의 인과관계를 경험한다"는 목표의 전제다. 같은 원인이 같은 결과를 내야 플레이어가 배울 수 있다.
- 현재 시각과 난수는 코어가 직접 만들지 않고 **인자로 주입**받는다.

## 1. 기록

**역할**: 모든 사건을 추가만 되는 로그로 보관한다. 하루 정산, 습관 계산, 인과 추적의 근거다.

| 항목 | 규칙 |
|---|---|
| 쓰기 | `append(event)`만 있다. 수정·삭제 함수는 만들지 않는다 |
| 번호 | `seq`는 1부터 빈틈 없이 증가 |
| 조회 | 구간, 유형, 인스턴스, `cause` 사슬 |
| 철회 | `retract` 사건 + 조회 시 철회 반영 옵션 |

**상태 변경 기록**: 상태 변경은 `state_changed` 사건으로 남긴다. 재생 일치 시험(`재생(초기 상태, 기록) == 현재 스냅숏`)은 슬라이스 이후로 미루되, 사건이 상태 변경의 근거가 되도록 형식은 지킨다.

**스냅숏**: 하루가 닫힐 때(`day_close`) 상태 스냅숏을 남겨 재생 비용을 줄인다.

**시험**: seq 빈틈 없음, 수정 시도 시 오류, 철회 반영, `cause` 순환 없음.

## 2. 난수

**역할**: 시드를 주입할 수 있는 난수. 테스트·밸런스·버그 재현을 위한 것이며 엄격한 결정론은 목표가 아니다. 사용처는 **이벤트 발생, 행동 판정, 문장 조각 선택**으로 제한하고, **변화 규칙은 쓰지 않는다** (0-5).

- 알고리즘은 32비트 연산 기반의 작고 빠른 생성기를 쓴다 (예: xoshiro128** 계열). 선택은 구현 시 확정한다.
- 흐름(stream) 분리는 필요해질 때 추가한다.
- 제공 함수: `uniform()`, `int(n)`, `chance(p)`, `pick(가중치 목록)`. 확률은 정수 분자·분모로 받는다.
- 저장에는 시드와 생성기 상태를 넣는다.
- **확률 결과는 예약 시점에 뽑아 저장한다.** 지연 효과를 발동 시점에 다시 뽑지 않으므로, 불러오기를 해도 어제의 선택과 오늘의 결과가 어긋나지 않는다.

**시험**: 같은 시드 동일 수열, `pick` 분포(허용 오차 안), 저장·복원 후 이어서 같은 수열.

## 3. 시계

**역할**: 게임 시간, 하루 경계, 주차, 부재 계산, 시연 모드.

### 3-1. 두 시계

| 시계 | 용도 |
|---|---|
| **실제 시각** | 하루가 열리는지, 며칠 비웠는지 판단에만 쓴다 |
| **게임 시각** | 하루 안의 분 단위 진행. 행동의 비용만큼 흐른다 |

### 3-2. 규칙

- 게임 시각: `{ week, day(1..7), minute(0..1439) }`와 절대 분 `abs`를 함께 가진다.
- 하루 경계는 **현지 시각 04:00** (설정값). 시간대는 설정으로 받는다.
- 실제 시각은 **인자로 주입**한다 (`RealClock` / `FakeClock`). 코어는 현재 시각을 직접 읽지 않는다. 시연 모드는 `FakeClock`을 넘기는 것이다.
- 시간은 행동·대기·약속으로만 흐른다. 고정 틱은 두지 않고 `advance(분)`을 부를 때마다 `tick{dt}`를 낸다.
- 하루 열기: `openDay(실제 now, 마지막 닫은 날)` → `{ opens, absentDays }`.
  - 마지막으로 닫은 날의 다음 04:00 이후여야 열린다.
  - 비운 날 수 `absentDays`는 **정수 일수**이고, 부재 보정은 `absence{ dt = absentDays × 1440 }`으로 변화 규칙에 전달된다.
- 스토리 일차는 **플레이한 날만** 오른다. 7일째가 닫히면 `week_close` 후 1일차로 돌아간다.

### 3-3. 시험

04:00 경계 직전·직후, 같은 날 두 번 열기 거부, 이틀·열흘 부재의 `absentDays`, 주 전환, `FakeClock`으로 7일 즉시 진행, 시간대 변경.

## 4. 저장

**역할**: 상태의 직렬화와 복원. **파일·저장소에 쓰는 유일한 모듈**이다.

- 형식은 버전이 붙은 JSON이다.

```
{ version, contentHash, seed, rng: {흐름별 상태}, clock, state: 스냅숏,
  awareness, habits, schedule, resources, logTail? }
```

- **정규 JSON**(키 정렬)으로 직렬화해 같은 상태가 같은 바이트가 되게 한다.
- `contentHash`는 콘텐츠 데이터의 해시다. 불러올 때 현재 콘텐츠와 다르면 경고하고, 마이그레이션이 있으면 적용한다.
- 저장 시점: `day_close`와 명시적 요청. 하루 중간 저장은 나중에 결정한다.
- **하루 중간 저장 (2026-11-10, 기본안)**: 엔진 입구(`src/core/session.ts`)의 저장은 위의 스냅숏이 아니라 **입력의 기록**이다 — `{ format, version, content, scenario, inputs, log: { events, digest } }`. 불러올 때 시나리오를 세우고 입력을 다시 넣어 돌린 뒤 지문을 대조한다. 엔진이 결정적이어서 가능하다. 스냅숏 복원(위 형식)은 플레이가 길어져 다시 돌리기가 느려질 때 하루 마감 지점에 더한다.
- 어댑터: 브라우저 localStorage, 파일(테스트·CLI). 어댑터 바깥은 저장 모듈의 존재를 모른다.
- 형식이 바뀌면 **버전을 올리고 이전 버전용 마이그레이션 스크립트**를 둔다.

**시험**: 저장→복원 후 상태 동일, 정규화 바이트 동일, 버전 불일치 오류, `contentHash` 불일치 경고, 복원 후 난수 이어서 동일.

## 5. 구현 순서와 의존

```
0 공통 약속 (번호·키·봉투)
   ├─ 1 기록   ← 봉투에 의존
   ├─ 2 난수   ← 독립
   └─ 3 시계   ← 독립
            └─ 4 저장 ← 위 전부에 의존
```

난수와 시계는 독립이라 어느 쪽을 먼저 해도 된다. 기록과 0장이 모든 시스템의 선행 조건이다.

## 6. 기반층 완료 기준

1. 위 시험이 모두 통과한다.
2. 코어가 현재 시각과 난수를 인자로만 받는다.
3. 빈 세계에서 시연 모드로 7일을 돌리고 저장·복원이 일치한다.
4. 변화 규칙이 난수에 접근하지 못한다 (함수 모양으로 강제).

---

## 7. 기본안 (확정 전)

1. **상태 값은 정수 단계 + 규칙 소유 진행도**로 둔다.
2. 상태 변경은 `state_changed` 사건으로 남기되, 재생 일치 시험은 슬라이스 이후.
3. **시간 단위는 분**, 하루 경계 **04:00**, 고정 틱 없음.
4. **인과(난수 금지)와 개입(난수 허용)을 분리**하고, 난수는 시드 주입만 한다.
5. 구현 언어는 **TypeScript**.
6. 번호 접두는 위 표 (필요하면 추가).

## 8. 구현 메모 (2026-11-05)

기반층 6장 완료 기준의 상태다.

| 기준 | 상태 | 확인 방법 |
|---|---|---|
| 1. 시험 통과 | 완료 | 난수 9 · 시계 11 · 저장 7 · 기반층 5 (전체 158) |
| 2. 코어가 시각·난수를 인자로만 받음 | 완료 | 금지 패턴 `core-nondeterminism`이 코어의 `Date.now`·`new Date(`·`Math.random`을 거부. 실제 시계는 `src/node/real-clock.ts` |
| 3. 빈 세계 7일 시연 + 저장·복원 일치 | 완료 | `test/foundation.test.ts` |
| 4. 변화 규칙이 난수에 접근하지 못함 | **부분** | 지금은 변화 규칙 모듈(statekey·chains·meaning·gate·compile)이 `rng.ts`를 가져오지 않음을 소스로 검사한다. **함수 모양으로 강제**하는 것은 규칙 실행기가 생길 때 한다 (규칙은 `(상태, 시각)`만 받는다) |

정한 것 (명세가 비워 둔 곳):
- `absentDays`는 **건너뛴 날 수**다. 11-03에 닫고 11-04에 열면 0, 11-06에 열면 2.
- 시간대는 **고정 오프셋(분)** 이다 (한국 +540). 서머타임은 다루지 않는다.
- `advance`는 하루 끝(1439분)에서 멈추고 넘친 분(`overflow`)을 알려 준다. 넘치면 호출한 쪽이 하루를 닫는다.
- `closeDay`는 7일째를 닫을 때 `weekClosed: true`를 내고 다음 주 1일차로 돌아간다 (주차 번호는 오른다).
- 저장의 `rng`는 흐름별 상태의 맵이고 지금은 `main` 하나다.
- 콘텐츠 해시는 `data/db.json`과 `data/vocab/*.json`의 sha256이다.

아직 정하지 않은 것: **하루 구간**(아침·낮·저녁·밤)의 정의. 시계 위에 얹는 값이며 시간 층 작업에서 정한다.
