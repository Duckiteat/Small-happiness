# 구현 계획 — 작업 단위 목록

작성일 2026-11-03 · 상태: **유지** (작업 상태표 ☐ ◐ ☑)

이 파일은 **위에서 아래로 차례로** 실행하는 작업 목록이다. 항목마다 끝나는 조건을 통과해야 다음으로 간다. 형식은 `make-bio-database`의 빌더 플랜(`docs/design/build-plan.md`)을 따랐다. 작성일 2026-11-03.

**북극성 (작가)**: 콘텐츠는 시스템에서 나온다. 사람이 지켜보는 맛이 나는, 자율로 살아가는 한 사람을 만든다. 시스템이 사실을 만들고 작가는 그 순간의 문장을 쓴다.

**순서 원칙**
- 시스템(코어) → 텍스트로 하루를 돌려 읽기 → 웹 화면. 프론트엔드부터 만들지 않는다.
- **검증하지 못하는 기능은 슬라이스에 넣지 않는다.** 능력은 그것을 반박할 시험과 함께, 또는 그 뒤에 온다.
- 슬라이스는 현관 + 냉장고, 인물 1명으로 한정한다 (`결정-기록.md`).

**분류**: 기반(지금) 1–8 · 세계 9–13 · 인물과 하루 14–19 · 표현 20–23 · 슬라이스와 검증 24–26 · 확장(슬라이스 밖) 27–32.

**공통 조건 (모든 항목)**
- `npm test` 전부 통과 · `npm run typecheck` 오류 0.
- 새 데이터는 **패치 관문**을 통과한다 (`node src/node/cli.ts validate`). 데이터 파일을 직접 고치지 않는다.
- 사전에 없는 단어를 쓰지 않는다. 새 단어는 `data/vocab/`에 먼저 넣는다.
- 임시 수치는 `tuned:false`로 표시한다. 모르는 값은 지어내지 않는다.
- 설계를 바꾸면 해당 명세와 `결정-기록.md`를 같은 커밋에서 고친다.
- 자동 생성 부록이 있으면 `appendix --check`가 통과한다.

**상태**: ☐ 대기 · ◐ 진행 · ☑ 완료.
