# 구현 계획 — 작업 단위 목록

작성일 2026-11-03 · **개정 1·2: 2026-11-10** · 상태: **유지** (작업 상태표 ☐ ◐ ☑)

이 파일은 **위에서 아래로 차례로** 실행하는 작업 목록이다. 항목마다 끝나는 조건을 통과해야 다음으로 간다. 형식은 `make-bio-database`의 빌더 플랜(`docs/design/build-plan.md`)을 따랐다. 단계·검증·일정은 `개발-계획서.md`에 있다.

**개정 1에서 바뀐 것**: 맨 앞에 **다음 구간(N1~N5)**의 작업표를 새로 두었다 (`개발-계획서.md` 4-2와 같은 단계). 지난 구간(S1~S8)은 기록으로 남기고, 표에 없던 11-07~08 작업(물건 관계·부엌 설비·온도)을 S4A로 더했다. 1~6부는 번호를 그대로 두고 상태를 11-10 기준으로 고쳤고, 각 항목이 어느 단계에 속하는지 적었다. 6부에 설계만 있는 개념(외면, 욕구·바람, 감각 넓히기)을 34~36으로 더했다.

**개정 2 (2026-11-10)**: 제출 일정이 정해졌다 — 시제품 **11-18(수)**, 공모전·창업 **11-20(금)**, 학교 **12월 초** (`개발-계획서.md` 1·8장). 작업마다 **언제까지**를 붙이고, 11-18 전에 하지 않을 것은 "11-20 뒤"로 미뤘다. N5를 제출물별로 다시 나눴다.

**북극성 (작가)**: 콘텐츠는 시스템에서 나온다. 사람이 지켜보는 맛이 나는, 자율로 살아가는 한 사람을 만든다. 시스템이 사실을 만들고 작가는 그 순간의 문장을 쓴다.

**순서 원칙**
- 시스템(코어) → 텍스트로 하루를 돌려 읽기 → 화면. 프론트엔드부터 만들지 않는다.
- **검증하지 못하는 기능은 시제품에 넣지 않는다.** 능력은 그것을 반박할 시험과 함께, 또는 그 뒤에 온다.
- 층위를 줄이지 않고 **상호작용하는 공간을 줄인다**: 인물 1명, 부엌 중심, 냄새 중심, 장면 하나에서 시작 (작가 2026-11-05).
- 작가 결정이 필요 없는 일을 먼저 하고, 결정이 필요한 일은 질문을 모아 한 번에 묻는다. 결정이 늦어지는 일은 건너뛰고 다음을 한다.

**분류**: 다음 구간 N1–N5 · 지난 구간 S1–S8 · 기반 1–8 · 세계 9–13 · 인물과 하루 14–19 · 표현 19A–23 · 시제품과 검증 24–26 · 확장 27–36.

**공통 조건 (모든 항목)**
- `npm test` 전부 통과 · `npm run typecheck` 오류 0.
- 새 데이터는 **패치 관문**을 통과한다 (`node src/node/cli.ts validate`). 데이터 파일을 직접 고치지 않는다.
- 사건을 만드는 기능은 **감사 위반 0** (`audit`). 원인이 빈 사건은 원천이거나 한계 등록부에 있다 (`gaps:check`).
- 사전에 없는 단어를 쓰지 않는다. 새 단어는 `data/vocab/`에 먼저 넣는다.
- 임시 수치는 `tuned:false`로 표시한다. 모르는 값은 지어내지 않는다.
- 아직 없는 기능은 `data/limitations.json`에 적는다.
- 설계를 바꾸면 해당 명세와 `결정-기록.md`를 같은 커밋에서 고친다. 코드·형식 변경은 `CHANGES.md`에 한 행.
- 자동 생성 부록이 있으면 `appendix:check`가 통과한다.

**상태**: ☐ 대기 · ◐ 진행 · ☑ 완료.
