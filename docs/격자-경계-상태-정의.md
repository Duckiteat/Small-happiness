# 격자 경계 상태 정의 (활성 영역의 내부와 경계)

작성일 2026-11-05 · 상태: **제안** (작가 제안, 같이 고민할 항목은 9장) · 근거: `결정-기록.md`(교차 도출), `축과-층위.md`, `품질판-명세.md`

## 0. 결론

- **개념은 이 프로젝트에 맞고, 새로 만들 것이 작다.** 지금 있는 구간 키(양자화), 서명(조건 묶음), 상태 이름(`meanings`)을 "격자 위의 영역"으로 보는 시각이다. 영역의 **내부**는 안정 상태, **경계**는 전이의 임계점이다.
- **격자는 파생물로 둔다.** 정의의 원천은 지금처럼 키 조건(범위의 곱과 합)이고, 격자는 거기서 만들어 **분석과 판정**에 쓴다. 정의를 두 곳에 두지 않는다.
- **세 가지 조건**이 붙는다: ① 구간이 4칸뿐인 축에서는 내부가 거의 안 생긴다(5장). ② 개념마다 **부분 공간**(그 개념이 언급하는 축만)에서 한다. ③ 잠긴 칸과 격자 가장자리의 처리 규칙이 필요하다.
- **희소 LU와는 대체 관계가 아니다.** 풀려는 문제가 다르다(3장). 이 프로젝트에서 이 개념이 맞는 것은 맞지만, LU가 틀린 것이 아니라 지금 해당이 없는 것이다.
- **검증한 것**: 아래 파이썬 파이프라인(`examples/grid-boundary/grid_boundary.py`)이 돌고, 자체 검증 네 가지가 통과한다(깊이 = 무차별 대입 거리, 상자 분해 = 영역, 테두리 + 씨앗 → 복원, 되먹임 문턱). **검증하지 못한 것**: 실제 감정·재질 데이터로 한 시험, 구간 경계값의 적절성, AI 연결.

## 1. 작가 제안 (요약)

인간의 감정과 재질 감각을 다차원 파라메터 공간에 정의하고, 이웃 셀 연산으로 활성 영역의 **내부**와 상태 전환의 **경계(테두리)**를 뽑는다.

1. 연속 축을 N차원 격자로 양자화한다.
2. 인식 수준에 맞게 해상도를 낮춰 덩어리(chunk) 단위로 관리한다.
3. 조건을 만족하는 셀을 1, 아니면 0으로 둔다.
4. 이웃 연산: 모든 이웃이 1이면 내부(안정), 일부가 0이면 경계(전이의 한계).
5. 내부를 지우고 경계 조건만 남겨 상태를 정의한다.

요구: ① 파라메터 매트릭스 설계 ② 경계 추출 알고리즘 ③ 내부/경계 판정 ④ 파이썬 파이프라인.

## 2. 이 프로젝트에서의 자리

### 2-1. 이미 있는 것과의 대응

| 제안의 요소 | 이 프로젝트에 이미 있는 것 | 이 개념이 더하는 것 |
|---|---|---|
| 양자화(격자) | 속도 법칙의 **구간 키**(온도 5℃, 습도 10), 단계 사다리 | 여러 축을 한 격자로 본다 |
| 활성 셀 = 조건 충족 | 모드의 **서명**(여유·에너지·긴장 높음/낮음), 상태 이름 `meanings` | 영역의 **모양**(내부, 경계, 깊이)을 계산한다 |
| 겹침 | 교차 도출(결정 기록: 5 지각 이상, 지각한 값으로만) | 겹침 = 두 영역 마스크의 AND |
| 경계 = 임계점 | 단계 경계, 결정 시점·비가역성 시험(구현 계획 16B) | 임계점을 정의에서 **자동으로 추출**한다 |
| 경계 근처 | 지연 규칙의 예고 구간(시간 기준) | 예고를 **상태 공간**에서도 정의할 수 있다(깊이 ≤ k) |
| 이름 없는 영역 | 이름 없는 겹침 보고서(논의 중) | 방문 격자 − 이름 있는 영역 = 후보 영역 |

### 2-2. 희소 LU와의 관계

- 이웃 프로젝트의 `compiler/sparse_lu.js`는 결합 Rodas3(강성 상미분방정식 적분기)의 **선형 단 행렬을 푸는 순서와 채움을 미리 계산**한다(머리 주석을 읽었다. 구현 전체는 읽지 않았다).
- 이 프로젝트는 그 적분기를 가져오지 않기로 했다(결정 기록, `DB-개념-이식.md` 7장). 그래서 지금은 해당이 없다.
- 두 개념은 같은 문제의 대안이 아니다. LU는 **연속 동역학의 수치 풀이**, 격자 경계는 **이산 상태의 이름과 임계점**이다. "여기서 이 개념이 더 어울린다"는 판단에는 동의하지만, 나중에 누적이 암시적 풀이를 요구하면 LU가 다시 필요해질 수 있다.

### 2-3. 층에서의 위치

- 격자는 **컴파일(빌드) 산출물**이다. 정의(키 조건)에서 만들고, 정의가 바뀌면 다시 만든다.
- 실행 중 판정은 미리 계산한 깊이 지도를 **한 번 읽는** 것이다.
- 감정과 물건 상태를 가로지르는 영역은 5 지각 이상에서, 하루씨가 지각한 값으로만 쓴다(결정 기록).

## 3. 설계

### 3-1. 파라메터 매트릭스

| 항목 | 설계 |
|---|---|
| 축 | 사전의 특징(사다리)이나 변수(여유, 긴장 등). 축마다 구간 수 L |
| 해상도 | 특징은 사다리의 **쓰는 칸**(0·1·3·5 → 4칸, 잠금 해제 후 6칸). 연속 변수는 별도의 구간 키(제안: 10구간) |
| 공간 | **개념마다 부분 공간**: 그 개념이 조건에 언급한 축만. 새 축이 생겨도 기존 개념은 안 바뀐다 |
| 저장 | 불리언 배열(밀집). 규모는 아래 표. 더 크면 좌표 집합(희소) |
| 원천 | 영역 = 상자들의 합집합(`[[(lo, hi), …축마다], …]`). 키 조건으로 쓸 수 있다 |
| 잠긴 칸 | 격자는 **쓰는 칸만**으로 만든다. 잠금을 풀면 격자를 다시 만든다 |
| 가장자리 | 기본: 축의 끝은 전이가 **아니다**(밖을 활성으로 봄). 선택으로 끌 수 있다 |

규모(불리언 배열): 구간 6칸 × 차원 8 = 1,679,616셀(약 1.7MB), 구간 10칸 × 차원 6 = 1,000,000셀(약 1MB). 차원 10 이상은 밀집으로는 어렵다. 개념이 부분 공간을 쓰므로 실제로는 2~4차원이 대부분일 것이다.

### 3-2. 경계 추출

이웃은 **축 방향 이웃**(von Neumann, 2N개)만 쓴다. 순서 있는 축에서는 대각선 이웃(3ᴺ−1개)이 의미가 약하다.

```
E(M)   = M ∧ ⋀ shift(M, 축, ±1)            침식: 모든 이웃이 활성인 셀
D(M)   = M ∨ ⋁ shift(M, 축, ±1)            팽창
B_in   = M ∧ ¬E(M)                          안쪽 테두리 (상태는 유지, 한 칸만 가면 벗어남)
B_out  = D(M) ∧ ¬M                          바깥 테두리 (인접한 다른 상태)
G      = D(M) ∧ ¬E(M) = B_in ∨ B_out        형태학적 그래디언트
depth(x) = min{ k : x ∉ Eᵏ(M) }            1 = 안쪽 테두리, 2 = 한 칸 안쪽, …
```

합성곱으로 쓰면 십자 커널 K(중심 0, 이웃 1)의 합 S = K∗M에서 **M(x)=1 이고 S(x)=2N이면 내부**, S(x)<2N이면 경계다. 부동소수 합성곱 대신 **불리언과 정수**를 써서 결과가 정확히 재현된다. 깊이는 침식을 반복한 횟수이고, 맨해튼 거리와 같음을 무차별 대입으로 확인했다(2D·3D, 가장자리 두 규칙).

### 3-3. 상태 판정

```
idx = 양자화(입력값)                  # 구간 번호
if not M[idx]:            → 밖
elif depth[idx] == 1:     → 경계 (임계점)
elif depth[idx] <= 1+k:   → 경계 접근 (예고 구간)
else:                     → 안정 내부
```

깊이 지도를 한 번 만들어 두면 판정은 배열 한 칸을 읽는 일이다. 측정으로 **판정 1회 약 0.4µs**(파이썬 함수 호출 포함)였다.

### 3-4. 파이프라인 코드

전체는 `examples/grid-boundary/grid_boundary.py`(numpy만 필요, `python3 grid_boundary.py`로 자체 검증). 아래는 핵심(이웃 연산, 경계, 깊이, 판정)이다.

```python
# ── 3. 이웃 연산 (von Neumann: 축 방향 이웃 2N개) ────────────────────────────
def _neighbors(mask, pad):
    """축마다 +1, -1 이동한 사본. 격자 밖은 pad 값으로 채운다."""
    out = []
    for ax in range(mask.ndim):
        for step in (1, -1):
            sh = np.full_like(mask, pad)
            dst = [slice(None)] * mask.ndim
            src = [slice(None)] * mask.ndim
            if step == 1:
                dst[ax], src[ax] = slice(1, None), slice(0, -1)
            else:
                dst[ax], src[ax] = slice(0, -1), slice(1, None)
            sh[tuple(dst)] = mask[tuple(src)]
            out.append(sh)
    return out


def erode(mask, pad=True):
    """모든 이웃이 활성일 때만 남긴다. pad=True: 격자 가장자리는 전이가 아니므로 밖을 활성으로 본다."""
    r = mask.copy()
    for n in _neighbors(mask, pad):
        r &= n
    return r


def dilate(mask):
    """이웃 중 하나라도 활성이면 켠다 (격자 밖은 비활성)."""
    r = mask.copy()
    for n in _neighbors(mask, False):
        r |= n
    return r


def inner_boundary(mask, pad=True):
    """영역 안쪽 테두리: 상태는 유지되지만 한 칸만 더 가면 벗어나는 셀."""
    return mask & ~erode(mask, pad)


def outer_boundary(mask):
    """영역 바깥 테두리: 영역에 처음 인접한 다른 상태의 셀."""
    return dilate(mask) & ~mask


def gradient(mask, pad=True):
    """형태학적 그래디언트 = 팽창 − 침식 (안쪽 테두리 ∪ 바깥 테두리)."""
    return dilate(mask) & ~erode(mask, pad)


def depth_map(mask, pad=True):
    """경계에서의 깊이(맨해튼 거리). 1 = 안쪽 테두리, 2 = 한 칸 안쪽, … 바깥은 0."""
    depth = np.zeros(mask.shape, dtype=np.int64)
    cur = mask.copy()
    d = 0
    while cur.any():
        d += 1
        nxt = erode(cur, pad)
        if np.array_equal(nxt, cur):  # 더는 깎이지 않는다: 경계가 닿지 않는 안쪽
            depth[cur] = INF
            break
        depth[cur & ~nxt] = d
        cur = nxt
    return depth


# ── 4. 판정 ──────────────────────────────────────────────────────────────────
def classify(idx, mask, depth, warn=0):
    """셀 하나를 판정한다. 깊이 표를 한 번만 읽는다.

    'outside'   영역 밖
    'boundary'  임계점 (안쪽 테두리)
    'near_edge' 경계에서 warn 칸 이내 — 예고 구간
    'interior'  안정 내부
    """
    if not mask[idx]:
        return "outside"
    d = depth[idx]
    if d == 1:
        return "boundary"
    if warn and d <= 1 + warn:
        return "near_edge"
    return "interior"
```

파일에는 이 밖에 양자화(`quantize`), 상자로 영역 만들기(`region_from_boxes`), 연결 성분(`label_components`), 상자 분해(`to_boxes`), 테두리 + 씨앗 복원(`boundary_representation`, `reconstruct`), 되먹임 문턱(`hysteresis`), 이름 없는 영역 후보(`unnamed_hotspots`)가 있다.

### 3-5. "테두리 조건만 남겨 정의하기" (제안의 5단계)

두 가지 길을 만들었고 둘 다 검증했다.

| 길 | 내용 | 평가 |
|---|---|---|
| **상자 분해** | 영역을 겹치지 않는 상자로 나눈다. 상자 하나 = 축마다 `[lo, hi]` 범위 조건의 곱 | **권장.** 지금의 `when` 조건과 같은 형식이라 데이터에 그대로 쓴다 |
| 테두리 + 씨앗 | 안쪽 테두리와 내부 성분마다 한 점만 저장하고 안으로 번져 복원 | 확인용. 영역이 작으면 이득이 작다 |

예: 영역 20셀, 안쪽 테두리 8셀, 씨앗 1개. 영역이 작거나 얇으면 테두리가 영역의 큰 부분이다. **테두리만 저장하는 압축 이득은 영역이 클 때만** 생긴다. 이 개념의 가치는 압축이 아니라 임계점의 의미에 있다.

## 4. 검증 결과 (실제 실행)

```
깊이 = 무차별 대입 거리: 통과
상자 분해 = 영역, 겹침 없음: 통과
테두리 + 씨앗 → 영역 복원: 통과
되먹임 문턱: 깜박임 7번 → 1번

불안 영역 (# 내부, + 경계, . 밖) — 행: 긴장 0~9, 열: 여유 0~9
..........
..........
..........
..........
..........
..........
+++++.....
####+.....
####+.....
####+.....
(8, 1) interior   (6, 4) boundary   (7, 2) near_edge   (3, 3) outside

겹침(불안 ∧ 지침) 셀 수: 8, 상자: [[(6, 7), (0, 3)]]
이름 없는 후보: [[[(6, 7), (6, 8)]]]
```

- 불안 = 긴장 6~9 & 여유 0~4(제가 지어낸 예). 격자의 위쪽과 왼쪽 끝은 **경계로 표시되지 않았다**(축의 끝은 전이가 아니라는 기본 규칙).
- 되먹임 문턱: 경계를 오가는 궤적에서 판정이 7번 뒤집히던 것이 1번으로 줄었다.

## 5. 문제와 위험

**5-1. 구간이 적으면 내부가 없다 (가장 중요).** 같은 크기의 영역에서 내부가 생기는지 쟀다.

| 한 축의 구간 수 L | 차원 N | 가운데 띠 영역 | 그 안의 내부 | 위쪽 절반 영역 | 그 안의 내부 |
|---|---|---|---|---|---|
| **4** | 2 | 4칸 | **0칸** | 4칸 | 1칸 |
| **4** | 3 | 8칸 | **0칸** | 8칸 | 1칸 |
| 6 | 2 | 16칸 | 4칸 | 9칸 | 4칸 |
| 6 | 3 | 64칸 | 8칸 | 27칸 | 8칸 |
| 10 | 2 | 64칸 | 36칸 | 25칸 | 16칸 |
| 10 | 3 | 512칸 | 216칸 | 125칸 | 64칸 |

- 사다리의 쓰는 칸은 4개(0·1·3·5)라서 **영역 대부분이 경계**가 된다. 내부/경계 구분이 의미를 가지려면 연속 변수(감정)는 **10구간 정도의 해상도**가 필요하다.
- 특징 사다리에서는 "내부"가 아니라 **깊이**(경계에서 몇 칸 떨어졌나)를 쓰는 편이 낫다.

**5-2. 잠긴 칸.** 쓰는 칸(0·1·3·5)만으로 격자를 만들면 칸 사이가 이웃으로 연결된다. 잠금을 풀어 6칸이 되면 격자가 바뀌어 경계가 이동한다. 그래서 정의의 원천은 **키 조건**으로 두고 격자는 파생물로 만든다(0장).

**5-3. 차원 폭발.** 구간 6칸 × 차원 8은 밀집으로 가능하지만(경계 추출 약 141ms, 깊이 지도 약 135ms) 차원 10 이상은 어렵다. 개념을 부분 공간으로 쪼개서 쓴다.

**5-4. 해상도 의존.** 한 칸 두께의 영역은 전부 경계다. 경계의 위치는 구간을 어떻게 자르느냐에 따라 달라진다.

**5-5. 상자로 쓸 수 없는 모양.** 대각선·곡선 조건(예: 긴장 + 여유 합이 얼마 이상)은 계단 모양으로 근사된다. 상자 분해는 정확하지만 상자 수가 많아질 수 있다.

**5-6. 이웃 정의.** 축 방향 이웃만 쓰는 것이 의미상 맞다고 보았지만, 대각 이웃을 쓰면 결과가 다르다. 작가의 의도가 어느 쪽인지 확인이 필요하다.

**5-7. 확인하지 못한 것.**
- 실제 감정·재질 데이터로 한 시험이 없다. 예시 영역은 모두 제가 지어낸 것이다.
- 구간 경계값(어디서 자르는가)의 타당성.
- 이웃 연산을 "인간의 인식 수준에 맞춘다"는 목적에 이 해상도가 맞는지.
- AI의 감각 수용 사이클과 이 구조가 실제로 맞물리는지(방향일 뿐 검증하지 않았다).

## 7. 3주 안의 최소판 (제안)

1. 개념 3~5개(예: 불안, 지침, 눅눅함, 끈적임)를 **키 조건(상자 합)**으로 정의한다.
2. 빌드 때 개념마다 부분 공간의 깊이 지도를 만든다.
3. 판정은 깊이 지도 조회로 한다. 경계 접근은 예고 구간의 상태 공간 버전으로 쓴다.
4. 겹침 영역을 마스크 AND로 구한다.
5. (여유가 되면) 이름 없는 영역 후보 보고서.

이식은 TypeScript로 새로 쓴다. 코어에는 부동소수 합성곱이 필요 없고 불리언과 정수만으로 된다.

## 8. 결정 기록과의 관계

- **교차 도출은 5 지각 이상, 지각한 값으로만**(확정): 이 개념도 그 규칙을 따른다.
- **아직 정하지 않음**(기록하지 않았다): 이 개념의 채택, 해상도, 가장자리 규칙, 경계의 종류.
