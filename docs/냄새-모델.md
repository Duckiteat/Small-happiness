# 냄새 모델 (원인 → 균주 → 유기화합물 → 냄새 종류)

작성일 2026-11-07 · 상태: **초안** (방향은 작가, 지식 내용은 서지 미확인) · 근거: 작가 지시(2026-11-07), 원 프로젝트 make-bio-database의 두 해상도(지식 / 시뮬레이션), `번짐-명세.md`, `음식-변화-모델.md`

냄새가 **왜 나고 어떤 냄새인가**를 사전의 지식으로 두고, 엔진은 그 지식에서 규칙을 만들어 쓴다. 엔진은 균주·화합물·냄새 이름을 모른다.

---

## 1. 두 해상도

| | 지식 해상도 (사전, 사람이 읽는다) | 시뮬레이션 해상도 (규칙, 엔진이 돈다) |
|---|---|---|
| 무엇 | 원인 → 균주 → 유기화합물 → 냄새 종류 | 원인의 단계에 이르면 물건에 대표 냄새 종류가 생긴다 |
| 어디 | `data/vocab/40-odor.json` 의 `odor_cause` · `strain` · `compound` · `odor_kind` | `src/core/odor.ts` 가 사슬에서 규칙을 만든다 (`odorRules`) |
| 이름 | 한국어 이름·설명 | `OBJ…/rule/odor_decay_spoiled` 같은 근거(via) |

```
냄새 원인 ─ 단계 ─▶ 균주 ─ 만든다 ─▶ 유기화합물 ─ 이런 냄새 ─▶ 냄새 종류
 부패        상함      슈도모나스       디메틸 이황화물              황 냄새
                       장내세균과       푸트레신 · 인돌 …            썩는 냄새  ← 대표 (가장 심각)
```

## 2. 지식 (사전)

| 분류 | 뜻 | 속성 |
|---|---|---|
| `odor_cause` 냄새 원인 | 부패 · 시어짐 · 익음 · 시듦 · 곰팡이 · 요리 | `feature`+`stages`(단계마다 `strains`와 냄새 세기 `strength`, 세기를 가진 특징은 `strength_feature`) 또는 `compounds`(요리처럼 균주 없이) |
| `strain` 균주 | 젖산균 · 슈도모나스 · 장내세균과 · 클로스트리디움 · 곰팡이류 | `produces`(만드는 화합물) |
| `compound` 유기화합물 | 아세트산 · 황화수소 · 푸트레신 · 지오스민 · 피라진류 … (12개) | `odor`(어떤 냄새인가) |
| `odor_kind` 냄새 종류 | 구수함 · 시큼한 발효 냄새 · 곰팡내 · 황 냄새 · 썩는 냄새 | `rank`(= 특징 `odor` 사다리의 칸 번호 = 심각도), `feature` |

- 모든 지식은 `verified: false`다 (서지로 확인하지 않은 일반 지식 초안). 확인하면 `true`로 바꾼다 (모르는 값은 지어내지 않는다).
- 사전이 참조(화합물의 냄새, 균주의 화합물, 원인의 단계·균주)와 `rank`가 사다리 순서와 같은지를 검사한다 (`validateVocab`).
- 지금의 사슬은 자동 생성 부록 3장에서 읽는다 (`node src/node/cli.ts appendix --write`).

## 3. 시뮬레이션

- **냄새 종류 특징 `odor`** (사전 `feature`): 칸 번호 0~5 = 없음 · 구수함 · 시큼함 · 곰팡내 · 황 냄새 · 썩는 냄새. 냄새의 세기(`smell`)와는 따로다. 음식의 몸(`body`)과 주방(`space`)이 가진다.
- **대표 냄새**: 단계의 화합물이 내는 냄새 종류 중 가장 심각한 것. 여러 종류가 섞이면 사다리의 `>=`(올리기만 함)로 가장 심각한 종류가 이긴다.
- **규칙은 만든다** (`odorRules`): 원인 특징(예: 부패)과 `odor`를 둘 다 가진 정의마다 단계별로 `원인@>=단계 → smell@>=그 단계의 세기, odor@>=대표 종류` (지연 0). 첫 주 데이터에서 28개. 냄새 세기는 예전에 음식마다 손규칙으로 복사했지만(28개, 9가지 표가 모든 음식에서 같았다) 원인의 지식이라 사전으로 옮겼다 — 새 음식은 부위·진행표·처음 상태만 적으면 된다.
- **주방으로 옮기기** (손으로 쓴 데이터, 주방 정의의 `kind_…` 규칙): 음식 중 가장 심한 종류가 K이고 주방 냄새가 있으면 주방 `odor`도 K. 주방 냄새가 가시면 종류도 사라진다 (`kind_clear`). 지금은 음식이 어느 방에 있는지가 없어 주방이 음식을 받는 곳이다 (`odor_reach`와 같다).
- **지각**: 주방의 `odor`도 하루씨가 알아채는 상태 키다 (감각은 후각). "주방 냄새=뚜렷함"과 "주방 냄새 종류=썩는 냄새"를 따로 알아챈다.
- **행동에 미치는 영향** (종류가 의미를 가진다):
  - 벌레는 시큼함 이상의 냄새에만 꼬인다 (구수한 요리 냄새에는 꼬이지 않는다).
  - 살피기는 시큼함 이상의 냄새 종류를 알아챘을 때만 한다.
  - 음식을 버리면 그 음식의 냄새 종류도 사라진다.

## 5. 확인 대기 (작가)

1. 냄새 종류 다섯 가지가 충분한가 (사다리가 여섯 칸이라 없음 + 5종이 한계다. 비린내·분변·알코올·과일향은 지금 가장 가까운 종류에 묶여 있다).
2. 부패의 단계마다 균주를 어떻게 배치할지 (쉼 → 젖산균, 상함 → 슈도모나스·장내세균과, 썩음 → 장내세균과·클로스트리디움은 초안이다).
3. 지식을 누가 어떤 자료로 검수할지.

## 6. 요리 (사람 ↔ 물체, 냄새의 원인)

요리하기(`cook`)는 사람과 음식(물체)의 상호작용이고, 냄새 원인 `cooking`(사전: 균주 없이 피라진류·알릴 이황화물 → 구수함)의 시뮬레이션이다.

| 항목 | 내용 |
|---|---|
| 언제 | **식사 준비 시간에만.** 일정에 `meal` 구간(사전 `presence`, 플레이어가 함께 보는 `observed: true`)을 두고, 제공 행동의 `during: ["meal"]`이 그 시간에만 고르게 한다. 첫 주 일정은 평일 07:20·19:40, 주말 08:00·12:00·18:30에 40분 (시험용 가정) |
| 무엇을 | 계란과 햄 (각 정의의 제공 행동 `cook`, 걸리는 시간 40분 임시값). 두부는 첫 주에 부패 과정을 끝까지 보려고 요리하지 않는다 |
| 앎 | 필요한 앎은 없다(`needs: []`). 믿는 보관 상태가 소멸이 아니고 먹을 수 있다고 믿을 때만 한다 (`when`, `when_meaning`) |
| 결과 | 재료는 쓰여서 소멸(`gone`)로 바뀐다 (버리기와 같은 표시: 냄새·냄새 종류·보관). 주방 냄새가 뚜렷해지고(`smell`) 종류가 구수함이 된다(`odor`) |
| 자기 행동의 결과를 안다 | 행동이 끝나면 그 행동이 바꾼 상태를 하루씨가 이해함으로 안다 (`Perception.learn`, 원인은 그 행동의 끝, 근거는 그 행동). 그래야 쓴 재료를 다시 요리하지 않는다 |
| 영향 | 구수한 냄새는 벌레를 부르지 않는다 (벌레는 시큼함 이상) · 살피기를 부르지 않는다. 3시간 뒤 냄새와 종류가 가신다 (`air_out`, `kind_clear`) |

- 지식과 데이터가 어긋나지 않게: 요리의 사슬이 말하는 대표 냄새(구수함)와 요리 효과가 주방에 적는 냄새 종류가 같다 (`test/cook.test.ts`).
- 한계: 요리가 욕구(배고픔)와 이어지지 않고 식사 시간 일정이 이끈다 · 만든 음식(결과물)이 없다 · 일정 구간이 시작되는 일이 사건이 아니라 요리의 원인 사건이 없다 (LIM020, LIM021).
