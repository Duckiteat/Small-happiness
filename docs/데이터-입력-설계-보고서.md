## 1. 데이터 입력 개념

### 1-1. 캐릭터 프로파일: 원본은 사람이 읽는 파일, 실행은 컴파일 결과

**대안**: 작가가 고치는 원본은 YAML(주석 가능, 들여쓰기로 읽힘). 빌드가 이를 JSON으로 바꾸고 검증한다. 이벤트는 이름이 아니라 **파라메터 키**를 참조한다.

```yaml
# characters/하루씨.yaml  — 작가 원본
id: 하루씨
work: 직장인
senses:                     # 감각 민감도 (1 둔함 … 5 예민). 인물마다 다름 (결정-기록 6)
  smell: 4
  touch: 2
  sound: 3
taste_bias: { 단맛: 0, 신맛: 1 }
homeostasis:                # 여유 모델 파라메터 — 임시값
  buffer_gain: 0.2          # tuned:false
  release_threshold: 0.8    # tuned:false
habits: [퇴근 후 바로 눕기]
```

- 빌드 출력 JSON에 각 값의 출처(`from: 작가 원본 줄 번호`)와 `tuned` 표시를 붙인다. 임시값은 `tuned:false`.
- 엔진·이벤트는 `senses.smell` 같은 **키**로만 읽는다. "하루씨"라는 이름을 코드에 넣지 않는다 (CLAUDE.md 코드 규칙).
- 두 번째 인물이 들어와도 이벤트는 그대로 두고 파라메터 값만 다르게 쓴다 (축과-층위 7).

### 1-2. 물건: 분류 프로파일 + 개별 물건 (차이만 기록)

**대안**: 분류가 기본값과 제공 행동을 가지고, 개별 물건은 **분류에서 달라진 것만** 적는다.

```yaml
# classes/냉장고.yaml — 분류 프로파일
class: 냉장고
zone: 주방
offers: [열기, 닫기, 보관]
material_of_body: 스테인리스   # 재질 트리의 노드 (1-5)
---
# items/주방-냉장고.yaml — 개별 물건
item: 주방 냉장고
is_a: 냉장고
override: { 크기: 대 }         # 그 밖에는 분류 값을 그대로 받음
```

- 실행용 DB에 들어갈 때는 `is_a`와 `override`가 **펼쳐진 한 줄**이 된다 (1-5의 해소 규칙과 같음).
- 같은 분류의 물건 수가 많아져도 분류를 고치면 전부 바뀐다. 개별 물건을 복사하지 않으므로 중복이 생기지 않는다.

### 1-3. DB를 축별로 나눌지, 붙일지

| 방식 | 장점 | 단점 | 판정 |
|---|---|---|---|
| 축마다 별도 DB | 작가가 축별로 관리하기 쉬움 | 한 물건의 상태를 보려면 여러 곳을 조인 — 느림 | 작성용으로만 |
| 한 덩어리로 합침 | 조회 한 번 | 축 하나를 고치면 전체 파일이 바뀜, 축 추가 때 깨짐 | 기각 |
| **하이브리드** | 작성은 축별 파일, 실행은 `물건 × 축 키` 한 테이블로 펼침 | 빌드 단계가 하나 더 필요 | **채택** |

근거: 축과-층위 6의 "새 품질을 추가해도 기존 골든 트레이스가 바이트까지 같아야 한다"를 지키려면 실행 테이블의 **열 추가**로만 축이 늘어야 한다. 축별 파일은 그 열을 만드는 입력일 뿐이다.

### 1-4. 이벤트·대사 자리: 맥락별로 한 번에 제시

**대안**: 작가에게 자리를 **맥락(장소·상태 묶음) 하나씩** 목록으로 준다. 작가가 승인하면 그 맥락의 대사와 이벤트를 한 번에 채운다.

자리 목록 형식:

| 자리 ID | 맥락 | 트리거 (상태 키) | 생성 반응물 | 필요한 대사 (분기 기준) |

#### 맥락 A — 냉장고 (사과 시나리오)

| 자리 ID | 트리거 | 생성 반응물 | 대사 분기 기준 |
|---|---|---|---|
| S-냉-01 | `사과:곰팡이@1` (곰팡이 시작) | 곰팡이(표시), 냄새(약) | 민감도 `smell` 높음 / 낮음 → 2종 |
| S-냉-02 | `사과:손상@터짐` | **진물**(잔류, 젖음) 생성, 원천 = 사과 | 놀람 + 손에 묻음 / 못 봄 |
| S-냉-03 | 잔류 `젖음 → 마름` (시간 전이) | — | 무시하는 독백 (습관 `배고프면 먹기` 여부) |
| S-냉-04 | 잔류 `고착` | 냄새 지속(공기), 재질 흡수에 따라 **자국** | 고착 경고 / 자국 분기 2종 |
| S-냉-05 | 행동 `물티슈로 닦기` | 잔류 젖음 → 감소, 고착 미제거 | 닦였지만 끈적임 (성공 아님) |
| S-냉-06 | 행동 `세제로 닦기` | 잔류 제거, 재질에 따라 자국 | 깔끔 / 누런끼 2종 |
| S-냉-07 | 행동 `선반 빼두기` · `담그기` | 옮김 → 잔류가 새 면으로 전달 / 합판이면 물먹음 | 빼둠 독백 / 담가서 부풀음 |
| S-냉-08 | 번짐 개체 `초파리` 자력 이동 발생 | 초파리(벌레) | 날아듦 / 못 알아챔 |

#### 맥락 B — 현관 (슬라이스 두 번째)

| 자리 ID | 트리거 | 생성 반응물 | 대사 분기 기준 |
|---|---|---|---|
| S-현-01 | 젖은 신발을 놓음 | 발밑 먼지(운반), 바닥 자국 | 신발장 옆 / 바닥 |
| S-현-02 | 장마 상태 3일째 | 신발 곰팡이 가속 (날씨 연결, 3장) | 습기 불평 / 무관심 |
| S-현-03 | 현관문 열림(자동) | 냄새 → 거실로 번짐 | 거실에서 맡음 |

> 맥락 B는 3장의 날씨 상태에 기대므로 3장 승인 뒤에 확정한다. 나머지 맥락(주방, 욕실, 거실, 베란다, 작은 방)은 맥락 A·B가 승인된 뒤 묶음으로 준다.

### 1-0. 조건 표기 (구현 완료)

조건은 단계 **키**로 쓴다 (`body:rot@>=spoiled`). 키의 순서는 사전 `levels`의 목록 순서가 정하고, 번호는 그 위치에서 파생된다. 단계를 끼워 넣어도 기존 조건의 뜻이 유지된다 (축과-층위 5). 번호 조건(`@>=2`)은 이제 거부된다. 이 변경으로 `examples/patches/fridge-chain.json`, 거부 말뭉치, 사전(`data/vocab/00-core.json`)의 단계 목록이 함께 바뀌었다 (시험 115개 통과).

### 1-0-2. 단계 사다리와 종결 (구현 완료)

- 단계는 **0~5 여섯 칸**이다. 칸 번호가 단계 숫자이고, 키 순서가 곧 강도 순서다.
- 지금 쓰는 칸은 **0 · 1 · 3 · 5**다. **2 · 4는 `locked`로 잠가 둔다.** 잠긴 칸을 조건에 쓰면 관문이 거부한다. 완성되면 사전에서 잠금만 풀면 된다 (데이터 구조를 바꾸지 않는다).
- **종결 단계 2개**(소멸 `gone`, 고정 `fixed`)는 사다리 밖에 둔다. 조건은 `=`로만 쓴다 (`body:rot@=gone`). 소멸은 원천이 실제로 없어진 경우이고, 버리기는 보관이라 소멸이 아니다. 고정은 자국처럼 세제로도 지워지지 않는 흔적이다.
- 종결 단계는 아직 사슬 연결(`canLink`)에 들어가지 않는다. 소멸을 가리키는 규칙끼리의 연결은 다음 단계에서 넣는다.
- 번호 0~5 중 쓰는 칸만 이름이 있다. 잠긴 칸(2·4)은 이름 없이 `s2`, `s4` 자리표로 둔다.
- 종결의 뜻 (작가 답변): **고정**은 상태가 진행된 뒤 남는 자국이다. 시간으로 사라지지 않는다. **소멸**은 행동이나 이벤트로 지워진 결과다. 고정 → 소멸 전이는 상호작용 규칙이 일으킨다.

### 1-5. 특성은 상위 묶음이 아니라 **이름마다 붙는 것**이다

처음 안(부모 값을 자식이 물려받는 재질 트리)은 기각한다. 대신 **특성(trait)을 사전 항목으로 두고, 재질과 가구에 붙인다.**

- 한 특성은 여러 대상에 붙을 수 있다 (물먹음: 합판, 목재 서랍장).
- 특성은 **자기 단계 축**을 가진다 (물먹음 = 마름 · 축축함 · 젖음 · 흠뻑). 보정은 그 단계 키에 따라 **계속** 바뀐다. 전체에 한 번 넣는 고정값이 아니다.
- 보정 표는 `meanings`와 같은 모양이다: 단계 키 조건을 위에서부터 보고, 처음 맞는 값을 쓴다. 조건이 달라지면 그 값이 바뀐다.

```yaml
# 재질 "합판" — 특성을 붙인다. 상속 없음.
material: 합판
traits:
  얼룩: 잘탐                  # 얼룩 축. 자국 생성 여부를 정함 (4-4)
  물먹음: 3                   # 세기 (확인 필요: 계수인지 최대 단계인지)
  곰팡이민감: 2               # 곰팡이 민감 등급 (확인 필요)
  드르륵스르륵: true           # 촉감·소리 특성 (확인 필요: 어떤 감각인지)
modifiers:                    # 단계 키 조건 → 곰팡이 가속 (×100 정수)
  - trait: 곰팡이민감
    when: 젖음@>=wet          # 젖음 축이 wet 이상이면
    accel: 150                # ×1.5
  - trait: 곰팡이민감
    when: 젖음@>=soaked       # 흠뻑이면 (위에서부터 보므로 이 줄이 먼저 와야 함)
    accel: 200                # ×2.0
```

- 위 예에서 보정이 **단계와 함께** 바뀐다: 마름일 때는 가속이 없고, 젖음부터 1.5배, 흠뻑이면 2배가 된다. 순서는 심각한 것을 위에 둔다 (4-2 규칙).
- 물에 담그면 합판의 젖음 축이 올라가고, 그 단계에서 곰팡이 가속이 커진다. 재질 특성이 행동의 결과를 자동으로 되돌려 준다.

### 1-6. 내구도: 재질 특성과 가구 특성의 합

- 내구도는 가구의 한 축 `body:durability`다 (온전 → 흠집 → 갈라짐 → 파손). 단계 키로 조건을 건다.
- 진행 속도는 축과-층위 8의 법칙을 그대로 쓴다: **기본 × 온도 × 습도 × 가공 × (1 + 가속의 합)**. 가속 항은 1-5의 modifiers에서 **현재 단계에 맞는 값만** 읽어 더한다.
- 가구 특성(예: 서랍장의 나사 접합, 얇은 판)은 같은 방식으로 기본값이나 가속에 더한다.
- **내구 배율 표** (사전 `durability`, 정수 ×100): 취약 50(0.5배) · 평균 100(1배) · 강점 150(1.5배) · 큰 강점 200(2배). 특성에 따라 부위에 이 배율 중 하나가 붙는다. 붙지 않은 부위는 평균이다.
- 가구 내구 배율은 **부위 배율의 평균**이다 (정수 합 ÷ 부위 수). 계산을 한 번의 나눗셈으로 끝내려는 선택이다.
- **계산 시점**: 특성의 단계가 바뀔 때만 다시 계산한다 (이벤트 방식). 매 시간 단위로 모든 특성을 훑지 않는다. 그래서 특성을 많이 붙여도 느려지지 않는다.

## 2. 손님 시스템

### 2-1. 일기장 (이벤트 묶음)

**대안**: 묶는 기준은 날짜가 아니라 **사건 사슬**(`chain` 번호)이다. 한 원인에서 이어진 사건(사과 곰팡이 → 터짐 → 진물 → 고착 → 자국)이 한 장의 일기가 된다.

- 카드 한 장 = 사슬 하나. 안에는 시각 순서의 사건, 그 사건에서 나온 대사, 플레이어가 한 행동을 함께 보인다.
- 사슬이 아직 열려 있으면 "열린 호", 닫히면 "닫힌 원"으로 표시 (상호작용-명세 2B-6과 같은 방식).
- 사슬 번호는 기록에 이미 남으므로 새 데이터는 필요 없다.

### 2-2. 주간 묶음

**대안**: 주차 루프(결정-기록 3)를 단위로 한다. 한 주의 카드를 날짜순으로 나열하고, 맨 위에 **주 요약 카드**를 둔다: 사건 수, 새로 생긴 자국 목록, 아직 고착된 잔류 목록, 미해결 사슬 목록.

### 2-3. 스티커 정렬 UI (커스텀 가능)

**대안**: 색·모서리·그림자·간격을 **테마 토큰 파일**로 둔다. 파스텔은 토큰 한 세트일 뿐 기본값이다. 사용자 커스텀은 토큰을 덮어쓰는 방식이며, 로컬 저장은 나중에 한다 (구현 계획상 웹은 뒤 단계).

```json
{ "theme": "파스텔", "palette": { "bg": "#FFF6EC", "sticker": "#F7D6E0" }, "radius": 14, "shadow": "soft" }
```

### 2-4 ~ 2-6. 빈칸에 대한 제안

작가가 비워 둔 항목이다. 제안으로 채운다. 채택하지 않으면 알려 달라.

- **2-4 사건 필터**: 장소·인물·상태 키로 일기를 거른다 (예: "냉장고 사건만").
- **2-5 되돌아보기**: 지난 주차와 이번 주차의 사건 수와 미해결 목록을 나란히 본다. 삶의 흐름을 보는 용도.
- **2-6 배치 프리셋**: 스티커 배치를 이름 붙여 저장하고 다시 불러온다. 같은 테마 토큰 안에서만 동작.

## 3. 날씨 (5a)

### 3-1. 원칙

- **날짜당 날씨 1개**를 정한다. 낮과 밤을 각각 날씨로 두지 않는다.
- 낮/밤은 **기온 보정 한 칸**(예: 밤 −3℃)으로만 반영한다. 이벤트는 시간 축(`time.day_part`, 축과-층위 8의 하루 구간)을 읽는다.
- "그런 경우"(연속 비, 열대야)는 날씨 한 날이 아니라 **날씨 열의 조건**으로 표현한다 (예: "비가 3일 이어짐").

### 3-2. 분류 (한국 · 온난 습윤 기준)

| 분류 | 강수 | 온도 구간 | 습도 구간 | 외부 먼지 | 기본 활성 | 영향 |
|---|---|---|---|---|---|---|
| 맑음 | 없음 | 보통 | 낮음 | 낮음 | 예 | 환기 효과 정상 |
| 구름 많음 | 없음 | 보통 | 보통 | 낮음 | 예 | — |
| 흐림 | 없음 | 보통 | 높음 | 낮음 | 예 | 빨래 건조 느림 |
| 비 | 있음 | 낮음~보통 | 높음 | 낮음 | 예 | 창 자동 닫힘, 습기 상승 |
| **장마** | 연속 비 | 보통 | 매우 높음 | 낮음 | 예 | 곰팡이 가속 최대 구간 (조건: 연속 3일 이상 — 임시) |
| 폭염 | 없음 | 높음 | 보통 | 낮음 | 예 | 부패 가속 |
| 열대야 | 없음 | 밤 고온 (밤 전용 보정) | 높음 | 낮음 | 예 | 밤 환기 불리 |
| 황사·미세먼지 | 없음 | 보통 | 낮음 | **높음** | 예 | 창 닫힘 유도, 먼지 유입 |
| 한파 | 없음 | 낮음 | 낮음 | 낮음 | **아니오** | 온난 습윤이므로 기본 제외 (hypothetical) |
| 눈 | 있음(고체) | 낮음 | 보통 | 낮음 | **아니오** | 드묾, 기본 제외 |

- 온도·습도 값은 축과-층위 8의 **구간 키**로 넣는다 (온도 5℃ 구간, 습도 10 구간). 날씨는 `ext.weather` 키로 외부 계에 속한다.
- 임계(연속 3일, 밤 보정 값 등)는 모두 **임시값(`tuned:false`)**이다. 실제 값을 지어내지 않는다.

### 3-3. 날씨가 닿는 곳

- 번짐: 날씨가 창 투과율을 바꾼다 (비 → 창 자동 닫힘). 투과율 자체는 `번짐-명세` 2장 값.
- 곰팡이: 장마·흐림의 **습도 구간**이 곰팡이 속도의 입력이 된다 (축과-층위 8 속도 법칙 그대로).
- 빨래: 흐림·비에서 건조가 느려진다 (세탁기 위치는 세계-설정 미정 — 이 부분은 보류).

## 4. 상태 고착 · 청소 · 자국

작가가 적은 흐름: **곰팡이 → 터짐 → 진물 → 방치 → 마름 → 고착 → 냄새 유지**. 이 흐름을 한 축으로 묶지 않고 **세 축**으로 나눈다.

### 4-1. 세 축

| 축 | 단계 (순서) | 뜻 |
|---|---|---|
| **손상** (`손상`) | 온전 → 갈라짐 → 터짐 | 표면이 망가진 정도. 터지면 잔류가 생긴다 |
| **잔류** (`잔류`) | 젖음 → 마름 → **고착** | 진물 같은 흘린 것이 마르고 붙는 정도. 시간으로 전이 |
| **자국** (`자국`) | 없음 → 흔적 (고정) | 상태가 진행되면 형성. 시간으로는 사라지지 않고, 상호작용으로만 소멸로 옮겨간다 |

- 냄새는 번짐 개체로, 원천은 잔류·곰팡이다 (번짐-명세 4 `needs`). 잔류가 **고착**인 동안 냄새가 계속 나온다 → "냄새가 고착화된다".
- 잔류 전이 시간은 **날씨의 온도·습도 구간**으로 빨라지고 느려진다 (3장).

### 4-2. 사과 연쇄 (시간 순)

| 순서 | 상태 변화 | 번짐 | 임계 |
|---|---|---|---|
| 1 | `사과:곰팡이@1` | 약한 냄새 | 임시 (`tuned:false`) |
| 2 | `사과:손상` 온전 → 터짐 | 진물 생성 (잔류 `젖음`, 운반체 = 놓인 선반) | — |
| 3 | 잔류 젖음 → 마름 | 냄새 유지 | 임시 |
| 4 | 잔류 마름 → 고착 | 냄새 지속, 자국 시작 | 임시 |
| 5 | 자국 없음 → 흔적 (재질 흡수 의존, 4-4) | 영구 | — |

### 4-3. 행동 × 상태 결과

| 행동 | 젖음 | 마름 | 고착 | 결과 원칙 |
|---|---|---|---|---|
| **물티슈로 닦기** | 감소 | 일부 감소 | **미제거** | 시간을 벌 뿐. 끈적임 |
| **세제로 닦기** | 제거 | 제거 | **제거** | 잔류 0, 냄새 원천 제거 |
| **버리기** | 원천 보관으로 이동 | 〃 | 〃 | 삭제 불가(번짐-명세 6-7) → 보관 장소로 옮김 |
| **옮기기 (빼두기)** | 전달 | 전달 | 전달 | 잔류가 놓인 면으로 옮겨감 — 새 면에 자국 가능 |
| **물에 담그기** | 씻김 일부 | 〃 | 일부 완화 | **합판은 물먹음 → 곰팡이 가속**. 꼼수처럼 보이지만 역효과 |

- 물티슈만 쓰면 냄새가 **고착화**한다. 세제로 닦아야 해결된다 — 이 차이가 "상태가 해결된다"의 정의다.
- 물에 담그기는 덜 나쁘게 보이지만 합판에서는 곰팡이를 키운다. 재질 트리(1-5)가 그 결과를 만든다.

### 4-4. 누런끼 (결정 지점)

작가가 "남을지 말지"를 고민한다고 적었다. **전역 결정을 하지 않고 재질 속성으로 둔다.**

- 재질에 **얼룩(잘탐)** 특성이 붙어 있다. 잘 타는 재질(합판)은 고착 잔류가 **자국**을 남기고, 아닌 재질(스테인리스·타일)은 남지 않는다.
- 세제로 닦으면 잔류는 지워지지만, 재질에 흡수된 자국은 고정 상태로 남는다. 자국은 시간으로 사라지지 않고, 행동(세제 닦기, 이벤트)으로만 소멸로 바뀐다. 이 차이가 '사라지지 않는 것'이다.
- 기각한 안: 항상 남김 (과함), 항상 안 남김 (흔적 축이 필요 없어짐).

### 4-5. 사전에 넣을 말

`잔류`, `젖음`, `마름`, `고착`, `진물`, `손상`, `갈라짐`, `터짐`, `자국`, `흔적`, `소거 불가`, `흡수`. 사전에 없으면 이 절의 규칙은 관문을 통과하지 못한다 (구현 4).
