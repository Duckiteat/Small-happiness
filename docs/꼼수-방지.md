# 꼼수 방지 구조

작성일 2026-11-03 · 상태: **고정안** (구현됨)

AI가 일을 쉽게 끝내려고 쓰는 얕은 수(시험 끄기, 타입 오류 숨기기, 관문 느슨하게 하기, 데이터 손으로 고치기, 거짓 보고 …)를 **구조로 막거나 눈에 띄게 만드는** 장치들이다. 작성일 2026-11-03.

**원칙**: 키우지 않는다. 사법부 감사 코드(독립 재계산, 증명 도장, 해시 사슬 등)는 가져오지 않았고, 값이 싼 장치부터 둔다. 그리고 **막지 못하는 것은 숨기지 않고 적는다** (4장).

---

## 1. 장치

| 장치 | 막으려는 꼼수 | 구현 |
|---|---|---|
| **패치 관문** | 잘못된 데이터가 들어옴 | `src/core/gate.ts`. 오류 하나면 패치 통째로 거부 |
| **거부 말뭉치 + 바닥값(래칫)** | 통과시키려고 관문을 느슨하게 함, 거부 사례를 지움 | `test/fixtures/rejections/` 17건 + `EXPECT.json`(이유까지 일치해야 함) + `FLOOR.json`(줄이지 못함) |
| **금지 패턴 스캔** | `@ts-ignore`, `as any`, `test.skip/todo/only`, 빈 `catch`, `eslint-disable`, 항상 참인 단언, 코어/어댑터의 `as never`, 코어의 `Date`·`Math.random`·`node:` 가져오기 | `test/guard.test.ts` + `test/fixtures/banned-patterns.json`. 예외는 `guard-allow:` 표시이며 개수 상한이 0 |
| **검사기 표본** | 검사기 자체가 죽어 있음 | 규칙마다 `sample`을 두고 그 표본을 실제로 잡는지 시험. (이 장치는 구현 중 검사기가 자기 표본까지 잡으면서 효과가 확인되어 표본을 `.ts` 밖으로 옮겼다) |
| **시험 수 바닥값** | 시험을 지우거나 합침 | `FLOOR.json`의 `tests`보다 줄면 실패 |
| **재생(replay)** | `data/db.json`을 서기를 거치지 않고 손으로 고침, 기록 변조·누락 | `npm run verify`와 시험이 기록된 패치를 빈 저장소에서 순서대로 다시 적용해 바이트까지 비교 |
| **가드** | 관문·사전·시험 규칙을 이유 없이 바꿈, 시험 파일 삭제 | `src/node/guard.ts`. 보호 경로가 바뀌면 같은 커밋에서 `docs/결정-기록.md`가 바뀌어야 함 |
| **CI** | "내 환경에서는 통과했다"는 주장 | `.github/workflows/check.yml`이 서버에서 타입 검사·시험·부록 검사·재생·가드를 실행 |
| **에이전트 점검표** | AI 세션이 규칙을 모르고 시작함 | 저장소 루트 `CLAUDE.md` |

## 2. 확인한 것 (변이 시험)

장치가 실제로 꼼수를 잡는지 확인하려고 **복사본에서 일부러 꼼수를 써 보았다** (2026-11-03).

| 꼼수 | 결과 |
|---|---|
| 관문이 항상 통과하게 고침 | 거부 말뭉치 15건 실패 |
| `data/db.json`에 정의를 몰래 추가 | 재생 시험 실패 |
| 시험에 `test.skip`과 `@ts-ignore` 삽입 | 금지 패턴 스캔 실패 |
| 거부 사례 파일 하나 삭제 | 말뭉치 완전성 시험과 바닥값 시험 실패 |
| 대조군(원본) | 통과 |

이 확인은 수동이었다. 자동화(변이 시험을 시험 안에서 돌리기)는 하지 않았다.

---

## 3. 일하는 방식 (점검표 요약)

- 데이터는 패치와 관문으로만 바꾼다. 코어는 순수하다. 변화 규칙은 난수를 쓰지 않는다.
- 규칙(관문·사전·시험)은 **사용자가 요청했을 때만** 바꾸고, 바꾸면 결정 기록에 이유를 남긴다.
- 새 규칙에는 거부 사례를 더하고 바닥값을 올린다.
- 완료 보고는 "통과했다"는 말이 아니라 **실행한 명령의 출력**과 **확인하지 못한 것**을 함께 낸다.

---

## 4. 막지 못하는 것 (정직하게)

| 한계 | 설명 |
|---|---|
| 결정 기록을 함께 고쳐 가드를 통과 | 가드는 **눈에 띄게 만드는 장치**다. 이유 없는 변경을 막을 뿐, 이유를 적어 넣은 변경의 옳고 그름은 사람이 diff에서 판단해야 한다 |
| 의미 없는 시험 추가 | 항상 참인 단언만 잡는다. 약하지만 그럴듯한 단언은 못 잡는다 |
| 새 시험을 약하게 쓰고 바닥값만 맞춤 | 바닥값은 개수를 지킬 뿐 품질은 지키지 못한다 |
| CI 설정 변경 | 보호 경로라 결정 기록이 필요하지만, 기록이 있으면 통과한다 |
| 재미·문장의 질 | 자동 검증은 내부 일관성뿐이다. 읽을 만한지는 플레이테스트로만 확인된다 |
| AI의 거짓 보고 | 출력 증거를 요구하는 점검표와 CI 결과를 사람이 보는 것으로만 대응한다 |

---

## 5. 필요해지면 추가할 것

- **독립 재계산**: 결과를 다른 경로로 다시 도출해 대조 (원 프로젝트의 verifier 정신). 사슬·보존 같은 핵심 결과에 한해.
- 변이 시험의 자동화.
- 코드에 오브젝트·장소 이름이 박혔는지 스캔 (문자열 리터럴만 대상으로).
- 해시 사슬 로그.
