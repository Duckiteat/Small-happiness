# 화면 계약 (뷰 모델)

디자인이 붙는 **약속**이다. 코어가 상태에서 계산해 내는 뷰 모델을 화면이 그리기만 한다. 작성일 2026-11-03. 상태: 초안.

**디자인은 코어 없이 이 JSON에 붙인다. 나중에 코어가 똑같은 모양을 내므로, 연결할 때는 데이터만 바꾸면 된다.**

---

## 1. 첫 장면: 냉장고 냄새

귀가한 하루씨가 현관문을 열자 이상한 냄새가 나고, 주방에서 상한 두부를 찾아 버리기까지의 한 장면이다. 이 한 장면에 지금까지 설계한 화면 장치가 모두 들어 있어서 골랐다.

- 줄글 속 눌리는 단어, 눌렀을 때 그려지는 **동그라미**와 뻗는 **선**, 선택지 노드
- 노드 라벨이 **감각 → 연상 → 구체**로 바뀌는 사다리
- **핵심**과 **주변부**의 구분
- 노드 **5개 상한**을 꽉 채우는 순간
- **열린 호 → 닫힌 원**
- 감기에 걸렸을 때 뜨지 못한 생각을 알리는 **점선 노드**

---

## 2. 여섯 상태 (`examples/view/fridge-smell/`)

한 장면을 여섯 상태로 나눈 스토리보드다. 디자인은 이 여섯 화면을 그리면 된다.

| 파일 | 상태 | 화면에서 확인할 것 |
|---|---|---|
| `01-arrive` | 현관문을 열었다. 눌리는 단어 `꼬릿한 냄새?`만 있다 | 지도가 비어 있다. 눌릴 수 있는 단어가 어떻게 보이는가 |
| `02-circle` | 단어를 눌렀다 | 동그라미(열린 호)가 그려지고 선이 뻗어 노드 3개(지각 1, 행동 2)가 생긴다 |
| `03-guess` | `킁킁` 뒤. 새 단어 `어디지.` | 노드 라벨이 `꼬릿한 냄새?` → `구수한가? 상한 건가?`로 **변한다**. 지나간 노드는 흐려진다 |
| `04-thing` | 주방. 냉장고 문틈의 허연 것을 봤다 | 라벨이 `상한 두부`로 구체화되고, **핵심**(중심)과 **주변부**(바깥 고리: 냄새, 벌레?)가 갈린다. 노드가 정확히 **5개** |
| `05-closed` | 두부를 버렸다 | 열려 있던 호가 **닫힌 원**이 된다. 처리한 노드는 완료 표시 |
| `06-cold` | 감기. 같은 현관 | 눌리는 단어가 없고, **점선 노드** `…`가 "머리가 무겁다"는 이유와 함께 보인다 |

## 3. 필드

| 필드 | 뜻 |
|---|---|
| `scene`, `place` | 장면 이름, 장소 |
| `event` | `{ id, status }` — 상태는 `none` / `open` / `closed` / `reopened` |
| `prose` | 문단의 목록. 문단은 조각(`text`, 눌리는 단어면 `anchor`)의 목록 |
| `anchors` | 눌리는 단어: `{ id, circle }` — 동그라미는 `none` / `open`(열린 호) / `closed`(닫힌 원) |
| `nodes` | 지도의 노드: `id`, `label`, `kind`, `ring`, `state`, 필요 시 `rung`·`hint` |
| `edges` | 선: `{ from, to, kind }` — `option`(고를 수 있음) / `link`(알고 있는 연결) / `unknown`(의심만 하는 연결, 점선) |

**노드 `kind`**: `percept`(지각, 사다리 칸 `rung` 필수) / `action`(고를 수 있는 행동) / `object`(물체) / `memory`(기억) / `ghost`(뜨지 못한 생각, `hint` 필수)

**`rung`**: `feel`(감각적 심상) → `guess`(연상) → `thing`(구체적 심상)

**`ring`**: `core`(핵심) / `periphery`(주변부) / `none`

**`state`**: `new`(방금 나옴) / `seen` / `done`(처리됨) / `faded`(지도에서 사라짐, 흔적)

**좌표는 없다.** 배치는 화면의 일이다. 다만 **같은 뷰에서는 같은 배치**가 나와야 한다(난수 금지).

---

## 4. 계약 규칙 (`parseView`가 보장한다)

1. 번호(앵커·노드)는 중복되지 않는다.
2. 간선은 있는 번호만 가리킨다.
3. 줄글의 앵커와 `anchors`가 서로 정확히 일치한다.
4. **보이는 노드(`faded` 제외, ghost 포함)는 5개 이하**다.
5. 이벤트가 `open`/`reopened`이면 닫힌 원이 없고, `closed`이면 열린 호가 없고, `none`이면 동그라미가 없다.
6. 지각 노드는 `rung`이 필수이고, 지각이 아닌 노드는 `rung`이 없다.
7. `ghost`는 `hint`(못 뜬 이유)가 필수이고, 다른 노드는 `hint`가 없다.
8. 보이는 핵심 지각 노드는 하나뿐이다.
9. 값은 정해진 목록 안에 있다(종류, 단계, 칸, 상태 …).

위반하면 거부되며, 15가지 위반이 시험으로 보호된다. 같은 지각 노드의 사다리 칸은 상태가 진행되는 동안 **올라가기만** 하는 것도 시험한다.

---

## 5. 디자인이 할 일

- 여섯 상태의 정적 화면 (데스크톱과 모바일)
- 동그라미(열린 호 / 닫힌 원), 선(`link`·`option`·`unknown` 구분), 노드(`percept`·`action`·`ghost` 구분, `core`/`periphery` 위치), 노드 상태(`new`·`seen`·`done`·`faded`)의 표현
- 줄글이 주인공이고 지도는 여백의 메모
- 색에만 의존하지 않는다 (접근성). 같은 정보를 **목록으로도** 보여 줄 방법
- 형식은 HTML/CSS/SVG이든 이미지든 상관없다. 정적 HTML이면 JSON을 읽어 그리게 바꾸는 것은 연결 단계에서 한다.

### 전환 연출은 차이로 계산한다

연속한 두 상태의 `diffView`가 바뀐 것을 알려 준다: 동그라미 변화, 추가·제거된 노드, 라벨 변화, 사다리 칸 이동, 이벤트 상태 변화, 늘어난 문단. 화면은 이것으로 "동그라미 그려지기 → 선 뻗기 → 라벨 바뀌기 → 호가 원으로 닫히기"를 연출하면 된다.

## 6. 연결 순서

1. **지금**: 디자인이 `examples/view/` 여섯 파일을 읽어 그린다. 클릭은 다음 상태로 넘어가는 목업이다.
2. **연결·디버깅**: 디자인을 받아 상태 재생기(이전/다음, JSON 보기)를 붙여 본다. 입력은 `{ type: 'attend', target: 앵커 또는 노드 번호 }`로 정한다.
3. **코어 연결**: 코어가 같은 모양의 뷰를 내게 하고, 픽스처와 대조하는 시험을 둔다.

**엔진 입구 (2026-11-10)**: 화면은 `Session`(`src/core/session.ts`) 하나로 엔진을 부른다.

| 부르는 것 | 하는 일 |
|---|---|
| `Session.start(db, vocab, 시나리오)` | 세계를 세운다 (아직 한 단계도 돌지 않음) |
| `advance(시각)` | 그 시각까지 차례가 된 단계를 돌리고 새 사건을 돌려준다. 나눠 진행해도 한 번에 돌린 것과 같다 |
| `advise(offer, at)` | 요정의 조언 (지금 시각). 하루씨가 다음에 고를 때 닿는다 |
| `view()` | 시계, 다음에 깨는 시각, 마지막 판(장면 `scene` 포함), 인물마다 고를 수 있는 선택지, 남은 조언 |
| `drain()` | 지난번 뒤로 생긴 사건 |
| `save(콘텐츠 해시)` / `Session.load(…)` | 입력의 기록으로 저장하고, 다시 돌려 되살린다 |

`view()`를 이 문서의 뷰 모델(노드·앵커)로 바꾸는 일과 앵커 입력(`attend`)은 아직이다.

## 7. 가정과 한계

- 5D 확인 항목(축 가족 6개, 층 9개, 단계 키 참조, 인물 인스턴스 차원, 하루 구간)은 **기본안으로 진행**한다고 가정했다. 코드가 적은 지금은 바꾸기 쉽다.
- `ghost`는 노드 5개 상한에 **포함**한다고 가정했다.
- 한 이벤트에는 핵심 지각 노드가 하나라는 가정이다.
- 라벨의 최대 길이, 노드 배치 알고리즘, 전환 시간은 정하지 않았다. 디자인이 정한 뒤 계약에 반영한다.
- 픽스처의 문장과 단어는 **설명용 초안**이다. 문장의 질과 호흡은 작가가 고친다.
