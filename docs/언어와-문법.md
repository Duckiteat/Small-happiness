# 언어와 문법

구현 언어, 시뮬레이터를 들고 오는 방식, 작가가 쓰는 문법을 정한다. 작성일 2026-11-03. 상태: 제안 (작가의 선택 대기).

---

## 1. 구현 언어: TypeScript 유지 (제안)

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **TypeScript** | 웹에서 그대로 실행(학교 과제에 가벼움), 엄격한 타입으로 AI의 얕은 수를 줄임(`strict`, `noUncheckedIndexedAccess`, `erasableSyntaxOnly`), 지금까지 코드와 시험 103개, 빌드 없이 실행 | 런타임 타입은 별도 검사 필요 (그래서 외부 입력은 모양 검사를 거침) | **채택** |
| JavaScript | 원 프로젝트와 같음 | 타입이 없어 AI가 어긋나기 쉬움 | 기각 |
| Rust (+WASM) | 가장 엄격하고 빠름. 원 프로젝트에 엔진이 있음 | 텍스트 게임에는 과함, 반복 속도가 느림, 웹 연결 비용 | 기각 (성능이 문제가 되면 그때) |
| Python | 쓰기 쉬움 | 웹 배포가 번거로움, 타입이 약함 | 기각 |

- 데이터 포맷은 **JSON**(패치), 사전도 JSON. 코어는 입출력이 없는 순수 모듈이다.

## 2. 시뮬레이터를 들고 오는 방식

원 프로젝트의 시뮬레이터는 상미분방정식 적분기, 대사 원장, 확률 엔진(SSA·τ-도약)과 Rust/WASM 실행기다. 우리 게임에는 쓸 곳이 없어서 **코드는 가져오지 않는다.**

가져오는 것은 **구조** 하나다.

```
 정의 저장소 + 시나리오 ──컴파일──▶ 불변 IR (숫자 인덱스 표) ──▶ 실행기
                                         │                         │
                                       irHash                 IR만 읽는다
```

- **컴파일러가 이름과 번호를 숫자 인덱스로 바꿔 동결한 IR을 만들고, 실행기는 IR만 읽는다.** 실행기는 "신발"도 "냉장고"도 볼 수 없으므로 "엔진은 이름을 모른다"가 규칙이 아니라 **구조**가 된다. AI가 실행기에 이름을 박는 꼼수 자체가 불가능해진다.
- IR의 해시를 기록에 남기면 어떤 데이터로 돌렸는지 추적된다.
- 도입 시점은 변화 규칙 실행기(구현 10)다. 지금은 규칙이 없어서 도입하지 않는다.
- 사법부 감사 코드(독립 재계산, 증명 도장)는 **가져오지 않는다.** 대신 가벼운 장치를 둔다 (`꼼수-방지.md`).

## 3. 문법의 계층

| 층 | 문법 | 쓰는 사람 | 상태 |
|---|---|---|---|
| 1. 구조 데이터 | JSON 패치 (정의·규칙·인물·이벤트의 뼈대) | AI·작가(도구 경유) | 구현됨 |
| 2. 패턴·조건 | `정의\|부위:특징@조건` (예: `OBJ000001\|body:rot@>=2`), 소유자 안에서는 `부위:특징@조건` | 규칙 작성자 | 구현됨. 복합 조건은 목록(AND)으로, OR은 규칙을 나눈다 (제안) |
| 3. **줄글 스크립트** | 작가가 줄글과 앵커를 쓰는 전용 문법 → **컴파일 → 패치 JSON → 관문** | 작가 | **제안 (4장)** |
| 4. 사전 | 모든 단어의 공식 키와 별칭 | 모두 | 구현됨 |

원칙: 3층은 편의일 뿐 **관문을 우회하지 못한다.** 컴파일러는 순수 함수(텍스트 → 패치)이고, 결과는 1층과 똑같이 관문을 지난다.

## 4. 줄글 스크립트 문법 (작가의 선택)

작가가 JSON에 문장을 써야 하면 호흡과 리듬을 잃는다. 그래서 줄글을 자연스럽게 쓰면서도 기계가 읽을 수 있는 문법이 필요하다.

### 4-1. 후보

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | JSON 문자열 안에 앵커 표기 | 컴파일러 불필요, 지금 바로 가능 | 글쓰기에 부적합, 따옴표·이스케이프 |
| **B** | 전용 경량 텍스트 문법 (파일 하나 = 이벤트 하나) → 컴파일 → 패치 | 줄글 중심, 우리 의미(정보 수준, 앵커, 사전)에 정확히 맞춤, 오류에 줄 번호 | 작은 파서와 시험을 직접 만들어야 함 |
| C | Ink / Yarn / Twine 같은 기존 도구 채택 | 편집기와 커뮤니티가 있음 | 우리 의미(정보 격차 링크, 사전, 관문)에 맞추려면 어댑터가 필요, 외부 의존, 학습 비용 |

**추천은 B**다. 파서는 작게 유지할 수 있고, 관문과 사전을 그대로 쓰며, 문장 조각이 작가의 원문 그대로 통과한다 (생성하지 않음).

### 4-2. B안 초안 (설명용)

```
# 이벤트: 냉장고 냄새
핵심: 음식|body:rot@>=2
주변: 주방|space:smell@>=1, 주방|space:bug@>=1
열림: 후각>=1, 시각(벌레)>=1
닫힘: 핵심 해소, 주변 <= 0

## 열림 / 후각 / 존재
현관을 열자 {꼬릿한 냄새?|킁킁} 가 났다.

## 킁킁 / 후각 / 방향
킁킁. {어디지.|탐색} 근데 은근 구수하네. #구수

## 탐색 / 시각 / 위치
주방 쪽이다. 냉장고 문 틈으로 {무언가|열어보기} 비어져 나와 있다.
```

규칙(초안):
1. 첫 줄은 `# 이벤트: 이름`. 이어지는 `키: 값` 줄이 이벤트의 뼈대(핵심, 주변, 열림, 닫힘)다. 값은 2층의 패턴 문법을 쓴다.
2. 장면 제목은 `## 이름 / 감각 / 정보 수준`. 감각은 사전의 `sense`, 정보 수준은 `info`(존재·위치·정체·정도).
3. 본문은 문장 단위로 쓴다. 한 문장은 한 줄이다.
4. 앵커는 `{보이는 말|동사}`. 동사는 사전의 행동·주의 단어다. 눌렀을 때 이어지는 장면 이름이나 행동 이름이 된다.
5. `#태그`는 사전에 있어야 한다 (예: `#구수`는 취향 편향 태그).
6. 모든 이름은 사전과 정의 저장소에서 해석된다. 해석되지 못하면 **줄 번호가 있는 오류**로 거부한다.
7. 닫힘 조건이 없는 이벤트는 컴파일 단계에서 거부한다.
8. 이름을 문장 안에 끼워 넣는 보간은 두지 않는다 (한국어 조사 문제). 문장은 통째로 쓴다.
9. 앵커를 눌렀을 때 뻗는 선택지 노드(마인드맵)의 라벨은 사전 단어의 한국어 이름이 기본이다. 이벤트가 덮어쓸 때만 `{말|동사|라벨}`로 쓴다 (`상호작용-명세.md` 2B-6).

### 4-4. 첫 구현 (2026-11-09, 작가: B안 · 시계 기준 하루 구간 · 첫 장면 하나)

파일: `content/events/*.ev` (파일 하나 = 이벤트 하나). `node src/node/cli.ts compile content/events/fridge-smell.ev` → 패치 → `validate` → `merge` (다른 원본과 같은 길). 파서는 `src/core/script.ts`, 장면 고르기는 `src/core/scene.ts`(7층).

```
# 이벤트: 냉장고 냄새
번호: EVT000001                       (처음은 EVT+1)
이유: …                               (필수)
핵심: PLC000002|space:odor            (심상 사다리를 타는 장소의 종류 키 — 그 사다리가 열리면 이벤트가 열린다)
닫힘: PLC000002|space:smell@<=none    (하나 이상, 모두 맞으면 닫힌다)
설명: …                               (여러 번)

## 현관을 열자 / 후각 / 느낌 / 저녁
현관을 열자 {꼬릿한 냄새?|킁킁}가 훅 끼쳤다.
```

- 장면 머리: `## 이름 / 감각 / 칸 [/ 하루 구간 / 모드]` — 칸은 심상 사다리(느낌·짐작·좁힘·정체), 하루 구간은 사전 `day_part`(아침 05~11 · 낮 11~17 · 저녁 17~22 · 밤 22~05, 임시값), 모드는 사전 mode. 모두 사전의 이름·별칭·키.
- **장면 조건 넓히기 (2026-11-09, 작가: 이미 있는 것 잇기 먼저)**: 칸 뒤에 조건을 더 쓸 수 있다 — 하루 구간(`저녁`) · 모드(`방전`) · `귀가`(들어온 지 30분 안) · `못 참음` · `카드:칭찬`(오늘 깬 뒤의 밖의 하루 카드) · `떠올림:김치`(물건 이름)·`떠올림:부패`(냄새 원인) · `종류:썩는 냄새`(믿는 종류) · `긴장>=쌓임`(내면 특징의 칸). 사전 `scene_cond`. 조건이 같은 수로 맞으면 파일 순서다.
- 머리 줄 `고침: …`이 있으면 그 패치의 이유가 된다 (처음 이유는 `이유:`에 남긴다).
- 구체성 우선: 조건이 더 많이 맞는 장면, 같으면 파일 순서. 감각 × 칸마다 조건 없는 기본 장면이 있어야 한다 (관문).
- 앵커 `{보이는 말|동사}`·`{보이는 말|동사|라벨}`: 동사는 사전 `attention`(킁킁·탐색·열어보기)·`action` 단어이거나 같은 이벤트의 장면 이름. 아직 누르는 길은 없다 (LIM043).
- 문장은 원문 그대로 저장하고 보인다 (보이는 글은 앵커의 말만 남긴다). 보간·태그는 없다.
- 오류는 줄 번호와 함께. 관문은 닫힘 없는 이벤트, 모르는 동사, 기본 장면 없음을 거부한다 (거부 시험).
- 기록: `event_opened` → `scene_shown`(장면 이름 · 칸 · 하루 구간 · 모드 · 원문 줄) → `event_closed`. 장면은 집에 깨어 있을 때만 바뀐다. 감사가 다시 고르고 원문을 바이트까지 맞춘다.

### 4-3. 작가에게 묻는 것

- A / B / C 중 어느 쪽이 편한가?
- B라면 앵커 표기 `{말|동사}`가 쓰기에 괜찮은가? (다른 괄호, 다른 구분자?)
- **더비슈즈 단락**과 **냉장고 냄새 단락**을 B 문법으로 직접 한번 써 보면 문법의 불편한 점이 가장 빨리 드러난다.
