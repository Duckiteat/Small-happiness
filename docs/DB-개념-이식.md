# 데이터베이스 개념 이식

별도 프로젝트 `make-bio-database`(생명과학 정의·기전 데이터베이스)의 설계 개념을 이 프로젝트의 말로 다시 정리한 문서다. 원문을 읽지 않고도 이해되도록 각 개념을 **자기완결적으로** 풀어 적고, 어디에 반영했는지 표시한다. 작성일 2026-11-03. 코드가 아니라 **설계 원리**를 가져온다.

읽은 범위: README, 작업 점검표(CLAUDE.md), 방향·삼권분립·사전/번역기·권한 문서, 난수 코드, 원장 스키마, 한계 등록부 앞부분. 엔진 내부와 테스트는 읽지 않았다.

**상태**: 적용 = 그대로 가져옴 · 변형 = 이 프로젝트에 맞게 바꿈 · 모듈 = 특정 모듈 도입 때 · 나중 · 보류 · 제외

---

## 1. 적용·변형한 개념

### 1-1. 고정 번호, 이름은 꼬리표 — 적용
- 원 개념: 모든 연결을 의미 없는 번호로 걸고, 이름은 번호에 붙은 꼬리표. 이름을 바꿔도 연결이 안 끊기고, 지운 번호는 다시 쓰지 않는다.
- 여기서의 뜻: 오브젝트·규칙·이벤트·문장 조각이 번호로만 서로를 가리킨다. 문장을 고쳐도 이벤트 연결이 유지된다.
- 반영: 기반층-명세 0-1

### 1-2. 정의가 구조와 규칙을 소유 — 적용
- 원 개념: 정의항(원천)이 분자의 구조와 규칙을 소유하고, 기전 단계는 규칙을 적용한 결과만 가볍게 담는다.
- 여기서의 뜻: 오브젝트 정의가 자기 부위와 변화 규칙을 소유한다. 사건 기록은 "어느 규칙이 적용됐다"만 담는다.
- 반영: 보고서 4-2

### 1-3. 묶음(파생 키) — 변형
- 원 개념: `바탕|부위:특징|위치` 형태의 파생 키. 인산화형은 새 개념이 아니라 특징 조합.
- 여기서의 뜻: 상태 키 `인스턴스|부위:특징`과 정수 단계. "더러운 신발"은 새 오브젝트가 아니라 상태다. 위치는 키가 아니라 인스턴스 속성으로 옮겼다.
- 반영: 기반층-명세 0-3

### 1-4. 단계 사슬의 자동 연결 — 적용
- 원 개념: 한 단계의 출력 키가 다른 단계의 입력 키와 같으면 자동으로 이어진다.
- 여기서의 뜻: 규칙의 `emits` 패턴과 다른 규칙의 `on` 패턴이 맞으면 이벤트·번짐이 자동으로 이어진다. "콘텐츠는 시스템에서 나온다"의 핵심 장치.
- 반영: 기반층-명세 0-3, 번짐-명세 7

### 1-5. 엔진은 이름을 모른다 — 적용
- 원 개념: 엔진 코드에 분자·위치 이름 금지. 사실은 데이터와 어휘에.
- 여기서의 뜻: 코드에 "신발", "냉장고"를 쓰지 않는다.
- 반영: 보고서 4-1

### 1-6. 통제 어휘 — 적용
- 원 개념: 위치·특징·종류 등을 목록의 값만 쓰고 별칭은 표준 값으로 바꾼다.
- 여기서의 뜻: 장소, 상태 특징, 행동 동사, 접촉 종류, 사건 이름의 허용 목록.
- 반영: 보고서 4-2. 초안은 미정 (결정-기록 7)

### 1-7. 관문(검증 게이트) — 적용
- 원 개념: 오류가 하나라도 있으면 패치 전체를 거부한다. 패치에는 `why`가 필수다.
- 여기서의 뜻: 이벤트·문장·규칙을 추가할 때 스키마, 번호 참조, 어휘, 사슬 연결을 검사하고, 오류가 있으면 통째로 거부한다.
- 반영: 보고서 8-3

### 1-8. 한계 등록부 — 변형
- 원 개념: `[대상 | 종류 | 요구]` 형식으로 모델이 못 하는 것을 데이터로 등록하고, 해결 데이터가 들어오면 **자동으로 resolved**가 된다.
- 여기서의 뜻 둘: (a) **인지 해금 조건** `[대상 | 단계 | 필요 조건]`, (b) **콘텐츠 공백 현황판** (필요한 문장 조각 대비 작성된 조각).
- 반영: 보고서 4-4, 8-3

### 1-9. 유한 저장소, 공급·분해 규칙 — 적용
- 원 개념: 보조 기질은 유한한 풀이고, 소비하면 줄고 바닥나면 단계가 멈춘다. 고갈은 오류가 아니라 결과다.
- 여기서의 뜻: 시간, 에너지, 돈, 소모품, 식재료. 포획 도구의 용량도 같은 구조.
- 반영: 보고서 4-3, 번짐-명세 6-5

### 1-10. 보존 감사 — 변형
- 원 개념: 매 시간 간격마다 질량이 이유 없이 생기거나 사라지지 않는지 검사한다.
- 여기서의 뜻: 자원이 이유 없이 생기거나 사라지지 않는지 테스트.
- 반영: 보고서 4-3

### 1-11. 관찰은 불변, 철회만 — 변형
- 원 개념: 실측 기록은 수정·삭제 없이 철회 표시만 허용.
- 여기서의 뜻: 활동 기록은 추가만 되는 로그. 하루 정산, 습관, 인과 추적의 근거.
- 반영: 기반층-명세 1

### 1-12. 난수·재현성 — 축소
- 원 개념: 시드와 궤적으로 같은 결과를 재현하는 엄격한 결정론. 과학적 재현성이 목적.
- 여기서의 뜻: 시드를 주입할 수 있게 해 테스트·밸런스·버그 재현에 쓴다. **엄격한 결정론은 목표가 아님.** 변화 규칙은 난수를 쓰지 않고(인과), 이벤트와 판정에만 쓴다(개입).
- 반영: 기반층-명세 0-5, 2

### 1-13. 사전/번역기 — 적용
- 원 개념: 기계 키 ↔ 사람말. 번역기는 **조회하지 추론하지 않는다.** 통제어는 결정론적 조회, 자유 서술은 원문 통과.
- 여기서의 뜻: 문장 엔진. 상태 키 → 작가의 문장 조각 조회. 서사 문장은 작가의 원문 그대로.
- 반영: 보고서 7-2

### 1-14. 모르는 값은 지어내지 않는다 — 변형
- 원 개념: 값이 없으면 `unmapped` 등으로 명시하고, 시험용 값은 `hypothetical` 시나리오에만.
- 여기서의 뜻: 밸런스 수치는 임시값으로 표시하고(`tuned:false`) 플레이테스트 뒤 확정한다.
- 반영: 보고서 4-2

### 1-15. 방향 문서·점검표·변경 기록 — 적용
- 원 개념: 세션이 바뀌어도 방향을 잃지 않도록 "방향 문서 + 점검표 + 변경 기록(범위·이유·영향·검증)"을 둔다.
- 여기서의 뜻: 혼자 AI와 작업하는 구조에서 세션 휘발에 대비. 이 `docs/` 폴더가 그 역할의 시작.
- 반영: 보고서 8-5

### 1-16. "검증이 능력을 앞지르지 않는다" — 적용
- 원 개념: 검증할 수 없는 기능은 먼저 만들지 않는다.
- 여기서의 뜻: 슬라이스에서 습관 후보 2~3개, 개체 3종 등으로 범위를 제한하는 근거.
- 반영: 보고서 12

## 3. 모듈 도입 때 쓸 개념 (성숙한 주제 모듈)

보건 정보는 시간이 지나면 낡을 수 있어서, 이 DB의 **값 관리 방식**이 그대로 도움이 된다.

| 개념 | 원 뜻 | 여기서의 뜻 |
|---|---|---|
| 출처 등급 | 값의 근거를 출처 축과 성질 축으로 계산해 등급화 (저장하지 않고 계산) | 보건 정보의 출처 등급. 공신력 있는 기관 자료만 |
| 추세 점검 | 같은 확인을 더 새 원본에 다시 돌려 일치 여부를 보고, 일정 기간이 지나면 다시 미확인으로 되돌림 | 보건 정보의 **유효기간**과 재확인 주기 |
| 결함 분류 | 결함을 종류별로 나눠 처리 방식을 정함 (발견은 고치지 않음, 공백은 등록 등) | 콘텐츠 오류·정보 오류·버그의 분류 |
| 외부 ID 원본 대조 | 확실한 것만 verified, 모르면 unmapped | 의학 용어·수치를 기관 원문과 대조 |

## 5. 이식 원칙

1. **개념은 이 프로젝트의 말로 다시 쓴다.** 원문 용어가 필요하면 출처를 밝힌다.
2. **코드를 복사하지 않는다.** 필요한 로직은 이 프로젝트의 요구에 맞게 새로 쓴다.
3. 이식한 개념마다 **해당 문서에 반영 위치**를 적는다.
4. 원 DB의 목적(과학적 재현성·현실 검증)과 이 프로젝트의 목적(인과 학습·생활 서사)이 다른 곳에서는 개념을 **축소**하거나 **버린다**.
5. 이 DB는 별도 프로젝트이므로 이 문서 외에 의존하지 않는다.
