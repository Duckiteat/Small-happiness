# 상호작용 명세 (이벤트의 정체와 구축 순서)

이벤트는 따로 쓰는 분기가 아니라 **상호작용의 고리에서 나온다.** 그래서 메인 시스템을 먼저 골라 중첩하고, 이벤트는 그 위에 얹는다. 작성일 2026-11-03. 상태: 초안.

**표기**: 확정 = 작가가 정함 · 초안 = 제안이며 확인 전

---

## 1. 상호작용이란 (초안)

**누가, 무엇에, 어디서, 무엇을 써서, 무엇을 했나 → 상태가 어떻게 바뀌었나.**

| 필드 | 뜻 |
|---|---|
| 행위자 | 인물, 또는 규칙·환경(날씨, 번짐 개체) |
| 동사 | 사전의 행동·접촉 단어 (닦기, 밟음, 쥠, 담김 …) |
| 대상 | 인스턴스 번호 |
| 장소 | 장소 번호 |
| 도구 | 쓴 물품 (선택) |
| 맥락 | 시간대, 기분 모드 같은 태그 |
| 결과 | 상태 변화 (효과 요청 → `state_changed`) |

기록에서는 기존 사건 유형이 그대로 쓰인다: 행위자가 시작한 것은 `action_done`, 물체끼리 닿은 것은 `contact`, 결과는 `state_changed`, 규칙이 낸 것은 `stage_advanced`. 모두 `cause`로 이어진다.

## 2. 이벤트의 정체 (확정)

**상호작용 자체, 그리고 상호작용 때문에 일어나는 또 다른 상호작용까지 본다.**

### 2-1. 고리의 세 차수

| 차수 | 무슨 일 | 예 (더비슈즈) |
|---|---|---|
| 1차 | 행위자 → 물체 | 하루씨가 신발을 신고 현관 바닥을 밟는다 |
| 2차 | **물체 → 물체** (규칙·접촉이 일으킴) | 밑창 먼지가 현관 바닥으로 옮겨진다 |
| 3차 | **물체 → 인물** (지각, 욕구) | 하루씨가 밑창의 더러움을 알아챈다 → 닦기가 후보 행동에 들어온다 |
| 다시 1차 | 인물 → 물체 | 물티슈로 닦는다 (자원이 줄고 오염이 내려간다) |

고리가 닫히므로 한 번의 사건이 다음 사건의 원인이 된다.

### 2-2. 이벤트는 고리의 "전환점"을 포착한 것

- 이벤트는 **포착 조건**(상태 + 최근 상호작용) 이 맞을 때 열리는 서사 단위다 (storylet).
- 전환점의 예: 인지가 오르는 순간, 모드에 진입하는 순간, 규칙의 단계가 오르는 순간, 처음 접촉이 일어난 순간, 약속 시각이 된 순간.
- 작가가 쓰는 것: **포착 조건, 장면(문장 조각), 선택지.** 선택지의 결과는 효과 요청으로만 표현한다.
- 시스템이 만드는 것: 사실(상태 변화)과 연쇄. 분기 트리를 손으로 엮지 않는다.

### 2-3. 이벤트의 출처 (분류)

| 출처 | 설명 | 난수 |
|---|---|---|
| 인물 ↔ 물체 | 자율 행동의 결과 | 작은 변주만 |
| 물체 ↔ 물체 | 규칙 사슬, 접촉 전달, 번짐 | **없음** (인과) |
| 환경 ↔ 물체·통로 | 날씨, 바람, 온도 변화 | 날씨 자체는 개입 |
| 외부에서 들어옴 | 밖의 하루 카드, 이웃, 택배, 약속 | 개입 (난수 허용) |

앞의 둘은 시스템에서 나오고, 뒤의 둘이 바깥에서 고리에 **주입**하는 것이다.

## 3. 오브젝트가 제공 행동을 소유한다 (초안)

물건이 자기가 줄 수 있는 행동을 선언한다 (The Sims의 "광고").

```
offers: [
  { verb: "닦기", needs: ["tool:물티슈"], effect: "OBJ|surface:dirt -1", satisfies: "불편" , cost: {시간, 에너지} }
]
```

- 인물의 자율 행동은 **알아챈 물건의 offers**를 후보로 점수를 매긴다.
- 새 물건을 추가해도 인물 쪽 코드를 고치지 않는다. 플레이어가 사 준 물건이 offers를 가진 채 들어오면 하루씨가 알아채고 쓴다.
- 고정 필드: `verb`(사전), `needs`(전제), `effect`(효과 요청), `satisfies`(해소하는 욕구), `cost`.
- 이 필드를 정의의 한 종류로 5A에서 같이 설계한다.

## 4. 추적 예시: 더비슈즈 고리

| 순서 | 일 | 시스템 | 사건 유형 |
|---|---|---|---|
| 1 | 하루씨가 귀가해 신발을 신은 채 현관에 선다 | 자율 행동 | `action_chosen`, `action_done` |
| 2 | 신발과 바닥이 닿는다 (밟음) | 접촉 | `contact` |
| 3 | 바닥의 오염이 오른다 | 세계 상태 | `state_changed` (cause: 2) |
| 4 | 하루씨가 감각 프로파일에 따라 밑창을 알아챈다 | 감각, 인지 | `stimulus_perceived`, `awareness_up` |
| 5 | **포착**: "밑창을 처음 알아챔" 이벤트가 열린다 (4비트 문장) | 이벤트 | `event_fired` |
| 6 | 닦기가 후보에 들어오고 선택된다 | 자율 행동 | `action_chosen` |
| 7 | 물티슈가 소모되고 오염이 내려간다 | 행동, 자원 | `action_done`, `state_changed` |

## 5. 구축 순서: 메인 시스템을 먼저 중첩한다 (확정)

이벤트가 나오려면 아래 층이 겹쳐져 있어야 한다. 각 층은 **이벤트 없이** 시험할 수 있다.

| 층 | 포함 | 이벤트 없이 하는 시험 |
|---|---|---|
| A. 공간 | 장소 그래프, 통로, 환경 특성 (구현 계획 5A) | 집 전체 패치가 관문 통과, 고립된 장소 없음 |
| B. 물체 | 정의의 부위·규칙·`offers`, 세계 상태 (9, 10) | 시간이 흐르면 `spoil → … → spread`가 단계적으로 진행 |
| C. 번짐 | 매질 3종, 운반체, 접촉 전달 (11, 12) | 신발 먼지가 이동 경로를 따라 남음. 보존 점검 통과 |
| D. 인물 | 컨디션, 욕구, 자율 행동 (14~18) | **빈 집에서 하루씨가 하루를 보내는 행동 기록**이 나옴 |
| E. 앎 | 인지, 습관 (19) | 증상 → 알아챔 → 이해, 반복이 기본값이 됨 |
| F. 이벤트 | 포착기 (19A) | 위 층의 전환점에서 열리고, 같은 상태에서 같은 이벤트가 열림 |
| G. 표현 | 문장 엔진, 하루 정산 산문 | 같은 상태에서 같은 후보 집합 |

- D까지가 "이벤트 없는 하루"다. 이것만으로 하루가 읽을 만한 기록으로 나오는지가 중요한 검증이다.
- 이벤트는 F에서 **패치로 추가**한다. 아래 층을 고치지 않는다.

## 6. 미정

1. 상호작용 기록을 `action_done`/`contact`로 충분히 표현할지, 별도 사건 유형(`interaction`)이 필요한지.
2. `offers`의 효과 표현 (효과 요청 문법, 도구 전제의 형식).
3. 포착 조건이 볼 "최근 상호작용"의 범위(시간 창) 표현.
4. 이벤트 선택지를 누가 고르는가: 하루씨의 자율 선택, 플레이어의 개입, 둘의 조합 (인물-명세의 "멈춤 지점").
5. 2차(물체 → 물체) 연쇄의 깊이 제한 (사슬 길이 상한 4단계와의 관계).
