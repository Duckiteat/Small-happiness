# 상호작용 명세 (이벤트의 정체와 구축 순서)

이벤트는 따로 쓰는 분기가 아니라 **상호작용의 고리에서 나온다.** 그래서 메인 시스템을 먼저 골라 중첩하고, 이벤트는 그 위에 얹는다. 작성일 2026-11-03. 상태: 초안.

**표기**: 확정 = 작가가 정함 · 초안 = 제안이며 확인 전

---

## 1. 상호작용이란 (초안)

**누가, 무엇에, 어디서, 무엇을 써서, 무엇을 했나 → 상태가 어떻게 바뀌었나.**

| 필드 | 뜻 |
|---|---|
| 행위자 | 인물, 또는 규칙·환경(날씨, 번짐 개체) |
| 동사 | 사전의 행동·접촉 단어 (닦기, 밟음, 쥠, 담김 …) |
| 대상 | 인스턴스 번호 |
| 장소 | 장소 번호 |
| 도구 | 쓴 물품 (선택) |
| 맥락 | 시간대, 기분 모드 같은 태그 |
| 결과 | 상태 변화 (효과 요청 → `state_changed`) |

기록에서는 기존 사건 유형이 그대로 쓰인다: 행위자가 시작한 것은 `action_done`, 물체끼리 닿은 것은 `contact`, 결과는 `state_changed`, 규칙이 낸 것은 `stage_advanced`. 모두 `cause`로 이어진다.

## 2. 이벤트의 정체 (확정)

**상호작용 자체, 그리고 상호작용 때문에 일어나는 또 다른 상호작용까지 본다.**

### 2-1. 고리의 세 차수

| 차수 | 무슨 일 | 예 (더비슈즈) |
|---|---|---|
| 1차 | 행위자 → 물체 | 하루씨가 신발을 신고 현관 바닥을 밟는다 |
| 2차 | **물체 → 물체** (규칙·접촉이 일으킴) | 밑창 먼지가 현관 바닥으로 옮겨진다 |
| 3차 | **물체 → 인물** (지각, 욕구) | 하루씨가 밑창의 더러움을 알아챈다 → 닦기가 후보 행동에 들어온다 |
| 다시 1차 | 인물 → 물체 | 물티슈로 닦는다 (자원이 줄고 오염이 내려간다) |

고리가 닫히므로 한 번의 사건이 다음 사건의 원인이 된다.

### 2-2. 이벤트는 고리의 "전환점"을 포착한 것

- 이벤트는 **포착 조건**(상태 + 최근 상호작용) 이 맞을 때 열리는 서사 단위다 (storylet).
- 전환점의 예: 인지가 오르는 순간, 모드에 진입하는 순간, 규칙의 단계가 오르는 순간, 처음 접촉이 일어난 순간, 약속 시각이 된 순간.
- 작가가 쓰는 것: **포착 조건, 장면(문장 조각), 선택지.** 선택지의 결과는 효과 요청으로만 표현한다.
- 시스템이 만드는 것: 사실(상태 변화)과 연쇄. 분기 트리를 손으로 엮지 않는다.

### 2-3. 이벤트의 출처 (분류)

| 출처 | 설명 | 난수 |
|---|---|---|
| 인물 ↔ 물체 | 자율 행동의 결과 | 작은 변주만 |
| 물체 ↔ 물체 | 규칙 사슬, 접촉 전달, 번짐 | **없음** (인과) |
| 환경 ↔ 물체·통로 | 날씨, 바람, 온도 변화 | 날씨 자체는 개입 |
| 외부에서 들어옴 | 밖의 하루 카드, 이웃, 택배, 약속 | 개입 (난수 허용) |

앞의 둘은 시스템에서 나오고, 뒤의 둘이 바깥에서 고리에 **주입**하는 것이다.

## 2A. 이벤트의 구조: 열림 · 연쇄 · 폐쇄 (작가 제안, 폐쇄 = 닫히는 핵심 조건이 있다는 뜻으로 확정)

이벤트는 **열려 있으며 연쇄적이며 폐쇄적**이다. 감각 하나 또는 여러 개로 느끼고 인식하는 것이 시작이다. 핵심이 되는 상태 변화나 오브젝트가 있고, 그 주변부를 처리하거나 핵심을 처리하는 구조다.

### 2A-1. 세 성질 (제 해석)

| 성질 | 뜻 | 검사할 수 있는 규칙 |
|---|---|---|
| **열려 있다** | 여러 감각 경로로 열린다. 경로가 달라도 핵심이 같으면 같은 이벤트다 | 진입 경로마다 첫 장면이 있고, 핵심 참조가 같음 |
| **연쇄적이다** | 처리하는 방식과 방치가 다음 이벤트로 이어진다 | 연쇄 후속이 실제로 존재하는 정의 |
| **폐쇄적이다** | 닫히는 조건이 있다. 끝없이 떠다니지 않는다 | 닫힘 조건이 없는 이벤트는 관문이 거부 |

### 2A-2. 감각과 인식 (초안)

감각마다 알려 주는 **정보의 종류**가 다르다. 인식의 해상도는 어떤 감각이 어떤 정보를 줬는가에 달려 있다.

| 감각 | 주는 정보 (초안) |
|---|---|
| 후각 | 존재, 정도 |
| 시각 | 정체, 위치, 정도 |
| 청각 | 존재, 위치(방향) |
| 촉각 | 정체, 정도 (닿아야 함) |
| 미각 | 정체 (먹는 것) |

- 정보 종류는 존재 / 위치 / 정체 / 정도 네 가지다 (사전에 `info` 분류로 추가 예정).
- 여러 감각이 겹칠수록 인식이 선명해진다. 같은 감각이라도 인물의 민감도가 곱해진다.
- 정체와 위치를 알아내는 **조사 행동**(냉장고 열어 보기)은 추가 감각을 얻는 행동이다.

### 2A-3. 핵심과 주변부

- **핵심**: 계통의 원천이 되는 상태나 오브젝트.
- **주변부**: 원천에서 파생된 개체와 그 영향 (냄새, 벌레, 번짐).
- 주변부는 **알아챔(인지 1단계)** 만으로 처리할 수 있다 (환기, 방향제, 닦기). 싸고 빠르지만 임시다.
- 핵심은 **정체와 위치를 알아야(인지 2단계)** 처리할 수 있다. 번거롭고 불쾌하지만 닫힌다.

### 2A-4. 생애: 열림 → 처리 → 닫힘 또는 연쇄

| 상황 | 결과 |
|---|---|
| 핵심이 해소되고 주변부가 임계 이하 | **닫힘** |
| 주변부만 처리하고 핵심이 남음 | 잠시 눌렸다가 **재열림** |
| 방치 | 계통이 확장되어 **후속 이벤트로 연쇄** (예: 주방 → 거실) |

### 2A-5. 예: 냉장고의 냄새

1. 하루씨가 귀가해 주방에서 냄새를 맡는다 (후각: 존재, 정도). 인식은 "뭔가 있다" 수준이고 정체는 모른다.
2. 주변부 처리: 환기, 방향제 → 냄새가 줄지만 원천이 남는다 (재열림 예약).
3. 핵심 처리: 냉장고를 열어 본다 (시각, 촉각: 정체, 위치) → 상한 음식을 알아챈다 → 꺼내서 **보관(쓰레기)** 으로 옮긴다 → 벌레의 먹이가 사라지고 냄새가 줄어든다 → 닫힘.
4. 방치: 벌레 단계가 오르고 거실로 번지는 후속 이벤트로 연쇄된다.

### 2A-6. 이벤트 정의 초안 (19A에서 확정)

```
event: {
  core:      핵심 상태 패턴 또는 오브젝트,
  periphery: [주변부 상태 패턴, ...],
  opens_on:  [ { sense, 최소 지각 }, ... ],       // 열림: 감각 경로 여러 개
  handle:    { periphery: [동사...], core: [동사...] },
  closes_when: [ 핵심 해소, 주변부 임계 이하 ],     // 폐쇄: 필수
  chains:    { ignored: EVT..., periphery_only: EVT... }
}
```

## 2B. 줄글 인터페이스: 눌러서 주의를 돌린다 (작가 제안)

화면은 **하루씨가 느끼는 하루를 줄글로** 적어 간다. 그 안의 단어나 문장을 누르면 분기가 열린다.

> 현관을 열자 **꼬릿한 냄새?** 가 났다.
> → (누름) 킁킁. **어디지.** 근데 은근 구수하네.
> → (누름) 주위를 둘러본다 …

### 2B-1. 줄글이 곧 지각 층

- 보이는 문장은 하루씨가 지금 느끼는 것이고, 눌리는 단어는 그가 **알아챈 자극**이다 (인물의 인지).
- 플레이어의 동사는 "시키기"가 아니라 **주의 돌리기**다. 하루씨는 자율로 움직이고, 누르지 않으면 습관과 모드가 알아서 한다.
- 이것이 "이벤트 선택지를 누가 고르는가"(6장 미정 4)의 답 후보다: 기본은 하루씨의 자율, 플레이어는 주의를 돌릴 수 있다.

### 2B-2. 링크는 정보 격차에서 생긴다 (초안)

링크를 손으로 엮지 않는다. 지각된 자극이 가진 정보와 아직 모르는 정보에서 결정론적으로 만들어진다.

| 아는 것 | 모르는 것 | 생기는 링크 | 누르면 |
|---|---|---|---|
| 존재, 정도 | 정체, 위치 | "꼬릿한 냄새?" | 킁킁 (후각 추가), 방향이 잡힘 |
| + 방향 | 위치 | "어디지" | 주위 탐색: 인접 장소의 감각이 추가됨 |
| + 위치 | 정체 | "냉장고" | 열어 본다 (시각·촉각) → 정체, 핵심 도달 |

- 누를 때마다 **추가 감각**이 들어와 인식 해상도가 오르고 새 링크가 생긴다 (연쇄).
- 핵심에 도달하면 핵심 처리 링크가 열리고, 해소되면 마지막 문장이 나오고 링크가 사라진다 (닫힘).
- 작가가 쓰는 것: **(자극, 아는 정보 수준)별 문장 조각**과 그 안의 앵커 표시.

### 2B-3. 반응은 인물에서 나온다

- "근데 은근 구수하네"는 감각 프로파일의 **취향 편향**에서 나온다. 같은 냄새에 대한 반응 문장이 인물마다 다르고, 반응이 긴급도(바로 확인할지)에 영향을 준다.
- 주의 돌리기(킁킁, 둘러보기)도 시간과 에너지를 아주 조금 쓴다.

### 2B-4. 구현에 필요한 것

- 사건 유형 `attention_directed` (플레이어가 주의를 돌림)와 행동 단어 `sniff`·`look`·`listen`·`touch`·`search` (사전에 추가 예정).
- 문장 조각 정의에 **앵커 표기**와 앵커가 가리키는 자극 참조.
- 링크 생성 규칙: 인식 상태(아는 정보)에서 결정론적으로. 난수 없음.

### 2B-5. 조심할 점과 미정

- **한국어 조사**(을/를, 이/가): 문장을 통째로 조회하면 문제가 적다. 이름을 끼워 넣는 곳이 생기면 조사 처리기가 필요하다.
- **링크 가시성**: 보이는 링크는 현재 지각된 자극에 한정하고, 서술이 흘러가면 **사라지게**(주의는 한정된 자원) 하는 안. 링크 수명은 미정.
- **시점 충돌**: "플레이어가 인물보다 더 많이 본다"(극적 아이러니)와 "줄글은 하루씨의 지각"이 부딪힌다. 서술자가 하루씨가 모르는 것을 살짝 비출지, 순수 1인칭 지각으로 갈지 정해야 한다.
- 누르지 않았을 때 하루씨의 자율 선택 규칙.
- 문장 조각 분량: 자극 × 정보 수준 × 감각 프로파일의 곱을 태그와 구체성 우선 선택으로 줄인다.

## 2C. 회상과 질문: 뭐든 눌러서 물을 수 있게 (작가 제안)

자극만 누르는 것이 아니다. **하루의 회상**도 물을 수 있다. 줄글의 어떤 단어든 단서가 될 수 있다. 예: "야근"을 누르면 하루씨가 그 일을 떠올린다. 목표는 "진짜 뭐든 가능하게" 하는 것이다.

### 2C-1. 눌러서 물을 수 있는 것의 종류 (초안)

| 종류 | 예 | 답의 출처 |
|---|---|---|
| 지각 | "꼬릿한 냄새?" | 지금의 자극과 인식 상태 |
| 회상 | "야근", "점심", "어제" | 인물의 **기억** (기록에서 파생) |
| 지식 | "이게 뭐지", "이거 어떻게 하더라" | 정의의 설명, 인물이 아는 것(인지 단계) |
| 감정·의도 | "왜 그랬지", "기분이 어때" | 컨디션, 모드, 여유 변화의 원인 이름표 |
| 계획 | "내일 뭐 하지" | 일정, 약속 |

### 2C-2. 닫힌 세계 원칙 (초안)

"뭐든 가능"을 지키는 방법은 모든 답을 쓰는 것이 아니라 **모든 질문의 답이 위 다섯 출처 중 하나에서 나오게** 하는 것이다.

- 답의 출처가 있으면 그 상태에서 문장 조각을 조회한다.
- 출처가 있어도 **정보가 없으면** 정의된 기본 응답을 한다 ("잘 모르겠다", "기억이 안 난다"). 기본 응답도 정보다: 방전한 날에 기억이 없다는 것은 그날의 상태를 말해 준다.
- 관문은 **출처가 없는 앵커**를 가진 문장 조각을 거부한다.

### 2C-3. 기억은 기록에서 파생된다 (초안)

- **기록은 진실이고, 기억은 하루씨가 겪은 것의 주관적 부분집합**이다. 기록은 하루씨가 모르는 것도 담지만 기억은 겪은 것만 담는다. 기억은 따로 저장하는 진실이 아니라 기록에서 **다시 계산할 수 있는 파생물**이다.
- **겪음**: 하루씨가 행위자나 지각자인 사건, 밖의 하루 카드.
- **현저성**: 여유 변화의 크기, 인지가 오른 순간, 처음 일어난 일, 감정 가치(취향 편향)로 정한다.
- **망각**: 날이 지날수록 현저성이 줄어든다. 난수 없이, 바닥을 둔다.
- **해상도**: 그날의 컨디션이 정한다. 방전한 날의 기억은 흐릿하다.
- **단서 조회**: 단서(단어, 물체, 장소, 사람, 시간)의 태그와 맞는 기억 중 현저성이 높은 것을 고른다.

### 2C-4. 예: 같은 "점심"을 누르면

- 평온한 날: "회사 앞 국밥집이었다. 국물이 뜨거웠고 옆자리 사람들이 시끄러웠다."
- 방전한 날: "…점심? 먹긴 먹었는데. 뭘 먹었더라."

### 2C-5. 하루 정산 = 회상 인터페이스

하루 정산 산문(구현 계획 21)이 그대로 회상 화면이다. 정산 속의 단어("야근", "냄새")를 누르면 제자리에서 펼쳐지는 회상이 나온다.

### 2C-6. 자유 입력 (나중)

글로 물어도 되게 하려면 사전과 이름 조회(`findByName`, `resolve`)로 **단서만 뽑는다**. 문장을 생성하지 않고, 못 알아들으면 기본 응답을 한다. 같은 장치가 이미 있다.

### 2C-7. 조심할 점과 미정

- **분량**: 사건 유형 × 해상도 × 감정 가치별 문장 조각이 곱으로 늘어난다. 태그와 구체성 우선 선택으로 줄인다.
- **고통스러운 기억**: 울었던 날을 되살리도록 강요하지 않는다. 하루씨가 피하거나 얼버무릴 수 있어야 한다.
- 기억과 기록의 차이가 앞서 열려 있던 **시점 충돌**(2B-5)을 풀 단서가 된다. 하루씨의 줄글은 기억/지각, 서술자의 한 문장은 기록을 쓴다.
- 현저성·망각의 구체 식, 겪음의 범위, 기억 용량 상한은 미정이다.

## 3. 오브젝트가 제공 행동을 소유한다 (초안)

물건이 자기가 줄 수 있는 행동을 선언한다 (The Sims의 "광고").

```
offers: [
  { verb: "닦기", needs: ["tool:물티슈"], effect: "OBJ|surface:dirt -1", satisfies: "불편" , cost: {시간, 에너지} }
]
```

- 인물의 자율 행동은 **알아챈 물건의 offers**를 후보로 점수를 매긴다.
- 새 물건을 추가해도 인물 쪽 코드를 고치지 않는다. 플레이어가 사 준 물건이 offers를 가진 채 들어오면 하루씨가 알아채고 쓴다.
- 고정 필드: `verb`(사전), `needs`(전제), `effect`(효과 요청), `satisfies`(해소하는 욕구), `cost`.
- 이 필드를 정의의 한 종류로 5A에서 같이 설계한다.

## 4. 추적 예시: 더비슈즈 고리

| 순서 | 일 | 시스템 | 사건 유형 |
|---|---|---|---|
| 1 | 하루씨가 귀가해 신발을 신은 채 현관에 선다 | 자율 행동 | `action_chosen`, `action_done` |
| 2 | 신발과 바닥이 닿는다 (밟음) | 접촉 | `contact` |
| 3 | 바닥의 오염이 오른다 | 세계 상태 | `state_changed` (cause: 2) |
| 4 | 하루씨가 감각 프로파일에 따라 밑창을 알아챈다 | 감각, 인지 | `stimulus_perceived`, `awareness_up` |
| 5 | **포착**: "밑창을 처음 알아챔" 이벤트가 열린다 (4비트 문장) | 이벤트 | `event_fired` |
| 6 | 닦기가 후보에 들어오고 선택된다 | 자율 행동 | `action_chosen` |
| 7 | 물티슈가 소모되고 오염이 내려간다 | 행동, 자원 | `action_done`, `state_changed` |

## 5. 구축 순서: 메인 시스템을 먼저 중첩한다 (확정)

이벤트가 나오려면 아래 층이 겹쳐져 있어야 한다. 각 층은 **이벤트 없이** 시험할 수 있다.

| 층 | 포함 | 이벤트 없이 하는 시험 |
|---|---|---|
| A. 공간 | 장소 그래프, 통로, 환경 특성 (구현 계획 5A) | 집 전체 패치가 관문 통과, 고립된 장소 없음 |
| B. 물체 | 정의의 부위·규칙·`offers`, 세계 상태 (9, 10) | 시간이 흐르면 `spoil → … → spread`가 단계적으로 진행 |
| C. 번짐 | 매질 3종, 운반체, 접촉 전달 (11, 12) | 신발 먼지가 이동 경로를 따라 남음. 보존 점검 통과 |
| D. 인물 | 컨디션, 욕구, 자율 행동 (14~18) | **빈 집에서 하루씨가 하루를 보내는 행동 기록**이 나옴 |
| E. 앎 | 인지, 습관 (19) | 증상 → 알아챔 → 이해, 반복이 기본값이 됨 |
| F. 이벤트 | 포착기 (19A) | 위 층의 전환점에서 열리고, 같은 상태에서 같은 이벤트가 열림 |
| G. 표현 | 문장 엔진, 하루 정산 산문 | 같은 상태에서 같은 후보 집합 |

- D까지가 "이벤트 없는 하루"다. 이것만으로 하루가 읽을 만한 기록으로 나오는지가 중요한 검증이다.
- 이벤트는 F에서 **패치로 추가**한다. 아래 층을 고치지 않는다.

## 6. 미정

1. 상호작용 기록을 `action_done`/`contact`로 충분히 표현할지, 별도 사건 유형(`interaction`)이 필요한지.
2. `offers`의 효과 표현 (효과 요청 문법, 도구 전제의 형식).
3. 포착 조건이 볼 "최근 상호작용"의 범위(시간 창) 표현.
4. 이벤트 선택지를 누가 고르는가: 하루씨의 자율 선택, 플레이어의 개입, 둘의 조합 (인물-명세의 "멈춤 지점").
5. 2차(물체 → 물체) 연쇄의 깊이 제한 (사슬 길이 상한 4단계와의 관계).
