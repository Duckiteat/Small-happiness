# 품질판 명세 (층 사이의 약속)

작성일 2026-11-05 · 상태: **초안** (작가 확인 대기 항목은 11장). 품질판은 층 사이의 유일한 약속이다. 이벤트와 문장은 품질판만 읽고, 층은 안에서 어떻게 계산하는지를 위 층에 알리지 않는다 (`축과-층위.md` 2장).

---

## 1. 두 라인

```
라인 A (세계)                 라인 B (사람)
0 기반  ─┬─ 1 공간            4a 외부계  ← 난수는 여기만, 예약 시점에 저장
         │  2 물체                 ↓
         │  3 인과            4b 내면
         │     │                   │
         │     └────────┬──────────┘
         └──(시계·번호는 두 라인 공통)
                        ↓
                  5 지각      세계와 사람을 둘 다 읽음
                  6 행동
                  7 이벤트    장면
                  8 표현
```

- 층은 아홉 개다. 외부계는 층 4의 앞 절반(4a), 내면이 뒤 절반(4b)이다.
- 라인 A와 라인 B는 **서로 읽지 않는다.** 5 지각에서 처음 만난다.
- 외부계의 영향은 **내면에만** 간다. 집에 직접 영향을 주지 않는다.

## 2. 이름 공간

| 이름 공간 | 담는 것 | 쓰는 층 | 값의 종류 |
|---|---|---|---|
| `time` | 시각, 일차, 주차, 하루 구간 | 0 | 정수 |
| `world.place` | 장소, 통로, 환경 특성 | 1 | 키, 단계 키 |
| `world.state` | 인스턴스별 특징의 양과 단계 | 2 (기록), 3 (갱신 요청의 소유자는 2) | 양(정수 1/1000), 단계 키 |
| `kit` | 보유 물품과 수량 | 2 | 정수 |
| `world.stimulus_source` | 자극의 원천과 세기 | 3 | 감각 키, 정수 |
| `ext` | 오늘의 외부 카드, 연락, 소식 | 4a | 카드 키, 태그 |
| `plan` | 일정, 약속, 고정 지점(anchor) | 4a | 시각, 키 |
| `self` | 여유·에너지·긴장, 모드, 상태이상, 습관 | 4b | 정수, 모드 키 |
| `perceived` | 하루씨가 지각한 것 (현저성 상위 N) | 5 | 항목 키, 단계 키 |
| `visible_to_player` | 플레이어에게 보이는 것 (`perceived`를 포함하는 넓은 집합) | 5 | 항목 키 |
| `aware` | 인지 단계 | 5 | 인지 키 |
| `memory` | 기억, 어제의 집 인상 | 5 | 항목 키, 정수 |
| `recent` | 최근 상호작용 | 6 | 사건 번호 |
| `scene` | 열린 장면, 처리 상태, 닫힘 | 7 | 장면 키, 상태 키 |

- 한 이름 공간은 **한 층만 쓴다.** 다른 층은 읽기만 한다.
- 값은 단계 **키**, 정수, 사전 키, 태그 중 하나다. 부동소수와 자유 문장은 넣지 않는다.

## 3. 읽기 규칙 (같은 단계 안)

| 층 | 읽을 수 있는 이름 공간 |
|---|---|
| 1 | `time` |
| 2 | `time`, `world.place` |
| 3 | `time`, `world.place`, `world.state`, `kit` |
| 4a | `time` |
| 4b | `time`, `ext`, `plan`, `self` |
| 5 | 위 모두 (`world.*`, `kit`, `ext`, `plan`, `self`) |
| 6 | `world.state`, `kit`, `plan`, `self`, `perceived`, `aware`, `memory` |
| 7 | 위 모두 |
| 8 | 위 모두 (읽기 전용) |

- **4b는 `world.*`를 읽지 않는다.** 집이 내면에 주는 영향은 5의 `perceived`를 거쳐 다음 단계에 들어간다 (5장).
- **6은 `world.stimulus_source`를 읽지 않는다.** 하루씨가 알아챈 것(`perceived`)만 후보가 된다.

## 4. 쓰기 규칙

- 이름 공간의 쓰기는 **소유한 층만** 한다. 다른 층이 바꾸고 싶으면 **효과 요청**(`effect_request`)을 낸다.
- `world.state`와 `kit`의 단일 작성자는 층 2다. 6과 7은 직접 쓰지 않는다.
- **외부계(4a)는 `world.*`와 `kit`에 효과 요청을 낼 수 없다.** 외부 카드의 영향은 `self`(내면)와 `plan`뿐이다.
- 모든 쓰기는 사건 기록으로 남고, 그 `cause`가 이어진다.

## 5. 되먹임 길 (다음 단계에 반영)

한 단계 안에서는 아래 층 → 위 층으로만 흐른다. 위에서 아래로 가는 길은 아래 네 가지뿐이고, **다음 단계에** 반영된다.

| 길 | 보내는 층 | 받는 층 | 무엇 |
|---|---|---|---|
| F1 | 6 행동 (장면의 선택지도 6을 거침) | 2 물체 | 효과 요청 (치우기, 버리기) |
| F2 | 6 행동 | 4b 내면 | `action_done`의 결과 (해냈다, 피곤하다) |
| F3 | 5 지각 | 4b 내면 | 알아챈 것의 정서적 영향 |
| F4 | 5 지각의 `memory` | 4b 내면 | **어제의 집 인상** (7장) |

- 집 환경이 컨디션을 **직접 읽어 깎는 길은 없다.** 인물 명세·시스템 명세의 "컨디션이 집 환경(파생)을 읽는다"는 F3로 바뀐다 (11장).
- 4a는 5와 6에서 받는 되먹임이 없다. 외부는 하루씨의 행동에 반응하지 않는다. (미정: 약속을 취소하는 행동은 `plan`에 영향을 주는가?)

## 6. 두 시야

- `perceived`는 **하루씨**가 지각한 것이고, `visible_to_player`는 **플레이어**에게 보이는 것이다. 후자가 전자를 포함한다 (극적 아이러니).
- 화면은 이 두 이름 공간을 읽어 그린다. 화면이 객관 상태(`world.state`)를 직접 읽어 그리지 않는다. 플레이어가 보는 범위는 점진 공개 규칙(인지 단계)이 정한다.
- 입력은 6 행동을 거쳐서만 들어간다. 화면은 상태를 쓰지 않는다.

## 7. 어제의 집 인상 (F4)

하루씨가 전날의 집에 대한 기억을 가지고 하루를 시작한다. "집에 들어오기가 무섭다"가 이 길에서 나온다.

- **만드는 곳**: 5 지각이 `day_close`에서 기록으로부터 **파생**한다 (난수 없음, 별도 저장 불필요).
- **무엇을 세나**: 그날 **알아챈 것**(`perceived`에 오른 것) 중 하루가 끝날 때까지 **해결되지 않은 것**. 알아채지 못한 것은 세지 않는다. 두 시야와 일관된다.
- **얼마나 세나**: 항목마다 `현저성 × 단계의 심각도`. 정체를 모른 채 불쾌했던 것(심상 사다리의 `feel` 단계)도 가중을 낮춰 센다. 상위 N개만 남긴다 (N은 임시).
- **언제 들어가나**: 다음 날 **귀가 시점**에 4b가 `anticipation`(긴장 +, 여유 −)으로 받는다. 크기는 인물 파라메터(`dread_gain`)가 정한다.
- **줄어드는 법**: 해결된 항목은 다음 날 인상에서 빠진다. 며칠 비우면 부재 일수만큼 약해진다 (망각).
- 수치(N, 가중, 이득)는 모두 **임시값**(`tuned:false`)이다.

## 8. 값과 규칙

- **의미 불변**: 기존 품질의 의미를 바꾸지 않는다. 바꿔야 하면 새 품질을 만들고 옛 품질에 폐기 표시를 한다 (번호를 재사용하지 않는 원칙과 같다).
- **중립 기본값**: 새 이름 공간이나 품질은 활성화 전에 아무것도 바꾸지 않는다 (곱 1, 게이트 통과, 태그 없음).
- **희소 조건**: 이벤트는 자기가 쓰는 품질만 언급한다. 이름 공간의 수를 모른다.
- **축 추가 불변 시험**: 중립 기본값으로 이름 공간을 더해도 골든 트레이스가 바이트까지 같아야 한다.

## 9. 난수의 자리

| 층 | 난수 |
|---|---|
| 0 | 생성기를 소유 |
| 1~3 | **없음** (함수 모양으로 강제) |
| 4a | 외부 카드를 뽑는 데에만. 예약 시점에 뽑아 저장 |
| 4b | 없음 |
| 5 | 경계에서만. 결과를 저장 |
| 6 | 판정에 한정 |
| 7 | 장면 선택 가중에 한정 |
| 8 | 문장 변주에 한정 |

## 10. 구현에 미치는 영향

- **구현 (2026-11-06)**: `src/core/board.ts`(판, 주인·읽기·되먹임 규칙, 값 검사)와 `src/core/step.ts`(층 순서, 층별 손잡이, 난수 배분). 3장의 "4b가 `self`를 읽는다"는 직전 단계의 자기 값으로 구현했다 (`PREV_READS`, 결정-기록 4장 "뼈대").
- 품질판은 **타입**으로 구현한다: 이름 공간별 읽기 전용 뷰와 쓰기 전용 핸들을 층마다 다르게 준다. 규칙 실행기에는 읽기 전용 뷰와 시각만 넘기므로, 난수와 다른 층의 쓰기가 닿지 않는다 (기반층 완료 기준 4번의 "함수 모양 강제"를 이 구조로 이룬다).
- 3과 4b의 "쌓임 → 임계 → 전이" 부품은 층 3이 돌아간 뒤 일반화한다.
