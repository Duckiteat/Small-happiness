# 사전 명세 (통제 어휘)

게임이 쓰는 **모든 단어에 공식 키를 하나씩 정하고**, 한국어 이름·영어 이름·별칭을 그 키로 연결하는 사전이다. 상호작용을 포함한 모든 단어가 대상이다. 상태: 초안, 첫 단어 목록 작성됨 (`data/vocab/`).

---

## 1. 쉽게 말하면

- 게임 데이터에서 "더러움", "오염", "때"가 같은 뜻이라면 컴퓨터 안에서는 **`dirt` 하나로** 다뤄야 한다. 그렇지 않으면 이벤트는 "오염"이라고 쓰고 규칙은 "더러움"이라고 써서 서로 이어지지 않는다.
- 사전은 이 연결표다. 작가가 어떤 말로 쓰든 공식 키로 바뀌고, 사전에 없는 말은 **오류로 거부**된다. 오타와 비슷한 말의 난립을 막는다.
- 이 사전이 있어야 이벤트, 문장 조각, 규칙을 많이 써도 서로 어긋나지 않는다. "콘텐츠는 시스템에서 나온다"의 바탕이다.

### 전달률이란

두 물건이 닿았을 때 오염이 **얼마나 옮겨 가는지**를 나타내는 숫자(0~1000, 천분율)다. 예를 들어 `밟음` 300이면, 오염된 신발이 바닥을 밟을 때 신발이 가진 양의 30%가 바닥으로 옮겨 간다. 닿는 방식(밟음, 쥠, 착용, 담김, 포개짐, 같은 표면)마다 값이 다르다. 지금 숫자는 **전부 임시값**(`tuned:false`)이고, 플레이하며 조정한다.

---

## 2. 구조

항목 하나는 다음과 같다.

| 필드 | 뜻 |
|---|---|
| `key` | 공식 키. 영소문자·숫자·밑줄. 코드와 데이터는 이것만 쓴다 |
| `ko` | 한국어 이름 (필수) |
| `en` | 영어 이름 (선택) |
| `aliases` | 별칭 목록. 모두 공식 키로 바뀐다 |
| `desc` | 설명 |
| `attrs` | 분류별 속성 (아래) |

파일은 `data/vocab/*.json`이며 분류(category) 배열이다. 같은 분류가 여러 파일에 있으면 항목이 합쳐진다. 나중에 콘텐츠 팩(성숙한 주제 모듈 등)이 자기 단어를 따로 파일로 추가할 수 있다.

---

## 3. 규칙

1. **한 말은 한 항목만 가리킨다.** 같은 분류 안에서 대소문자, 띄어쓰기, 하이픈, 밑줄, 가운뎃점 차이를 없앤 말이 두 항목을 가리키면 오류다.
2. **키는 분류 안에서 유일하다.**
3. **뜻이 여러 개인 말**(예: "냄새"는 상태 특징이면서 번짐 개체)은 분류를 알려 줘야 한다. 분류 없이 전역 조회하면 둘 이상으로 나온다.
4. **분류 사이 참조는 키로 걸고 검사한다.** 번짐 개체가 가리키는 매질·감각이 실제로 사전에 있어야 한다.
5. **임시값은 임시값이라고 적는다.** 전달률에는 `tuned`가 필수이고, 모르면 지어내지 않는다.
6. **지운 키는 다시 쓰지 않는다** (이름을 바꾸면 옛 이름은 별칭으로 남긴다).

---

## 4. 분류

| 분류 | 뜻 | 속성 |
|---|---|---|
| `sense` | 오감 | — |
| `feature` | 상태 특징 (더러움, 상함, 냄새 …) | `levels` 단계 이름 목록 (2개 이상) |
| `medium` | 번짐 매질 (공기, 운반, 자력 이동, 흐름) | `in_slice` 슬라이스 포함 여부 |
| `spreader` | 번짐 개체 (냄새, 벌레, 먼지) | `medium`, `stimulus` (각각 사전의 키) |
| `edge_kind` | 장소 사이 통로 종류 | — |
| `mobility` | 고정 / 이동형 (사람 혼자 옮길 수 있는 모든 것) | — |
| `contact` | 접촉 종류 (밟음, 쥠, 착용, 담김, 포개짐, 같은 표면) | `transfer` 전달률, `tuned` |
| `action` | 행동 (닦기, 환기, 설치, 보관, 비우기, 판매, 옮기기) | — |
| `event_type` | 사건 유형 (기록이 받는 말) | — |

앞으로 추가할 분류: 장소, 오브젝트, 물품, 습관, 인물 특성, 문장 태그, 접촉 외의 상호작용 동사 등. 모든 단어를 사전에 두는 것이 목표다.

---

## 5. 코드와의 연결

- `src/core/vocab.ts`: 사전 검증과 조회 (`resolve`, `lookup`, `has`, `entry`).
- `src/node/vocab-files.ts`: 폴더에서 파일을 읽어 합친다.
- **기록은 사전의 사건 유형만 받는다.** 사전에 없는 유형은 추가 시점에 거부된다.
- 사전 데이터가 검증을 통과하는지는 테스트(`test/vocab.test.ts`)가 확인한다. 데이터를 고쳐서 규칙이 깨지면 테스트가 실패한다.

---

## 6. 단어 추가 절차

1. `data/vocab/`의 해당 분류에 항목을 추가한다 (`key`, `ko` 필수).
2. 비슷한 말은 `aliases`에 넣는다. 다른 항목과 같은 말로 취급되면 테스트가 오류로 알려 준다.
3. `npm test`로 검증한다.

---

## 7. 미정 사항

1. 첫 단어 목록(`00-core.json`, `10-events.json`)은 초안이다. **단어와 별칭을 작가가 검토**해야 한다.
2. 장소, 오브젝트, 물품, 문장 태그 같은 나머지 분류를 어떤 순서로 채울지.
3. 한 단어의 여러 뜻(예: "냄새")을 문장 조각에서 어떻게 구분해 쓸지.
4. 영어 이름을 필수로 할지 (현재는 선택).
